# 记忆巩固 · 执行手册（4 个方法）

> 详细步骤、验收线与 Agent 契约。每个方法的 checkpoint 都是**可判定**的，无法判定就说明这一步没做扎实，不要靠感觉通过。

### 1. 主动回忆练习（`active-recall`）

*Active Recall*

**关掉资料，凭记忆主动提取信息，把「看着眼熟」换成「真的想得出」。**

- **分类**：记忆巩固
- **循证等级**：high —— 有较强实验证据支持（多项对照研究）
- **版本**：0.1.0　**许可**：CC0-1.0

**适用场景**

- ✓ 感觉记住了但考不出来
- ✓ 背了就忘
- ✓ 考前冲刺

**不适用**

- ✗ 第一次接触全新材料（此时还没东西可提取）

**入参**

- `material`（**必填**，string）：要记住的材料（关键词表/步骤/公式/问答对）
- `items`（可选，integer），默认 `10`：本轮条目数上限

**执行步骤**

1. **切成可独立提取的条目**（`chunk`，约 5 分钟）
   - 做什么：把材料拆成互不依赖的最小单元（一个术语、一组步骤、一个问答对）。每条控制在 20 秒内能说完。
   - 验收线：条目数 ≥ 3，且每条都不需要看其他条目才能回答
   - 产出：item list
2. **合上资料，空白输出**（`blank-sheet`，约 8 分钟）
   - 做什么：严禁 Agent 先展示答案。让 Agent 或用户在不看原资料的情况下，把每条内容写出来。允许写不出，但不允许对照修改。
   - 验收线：产出了一份明确标记了「想不出」的完整回忆稿；回忆稿在核对前不可修改
   - 产出：blank-sheet recall
3. **对照差异**（`diff`，约 5 分钟）
   - 做什么：现在才打开原资料，逐条标：✓ 全对 / △ 漏了关键点 / ✗ 完全错。
   - 验收线：每一条都有 ✓/△/✗ 标记，且 △ 行的「漏了什么」被具体写出
   - 产出：diff report
4. **给分并写入调度**（`score`，约 3 分钟）
   - 做什么：为每条给 self_score（0=完全想不出，5=毫不费力）。把 ✗ 和 △ 的条目写入复习队列，next_due 由 SM-2 计算。
   - 验收线：全部条目都有 0-5 的分数，且所有 ≤4 分的条目都有 next_due 时间
   - 产出：SRS entries

**Agent 契约**

- 输入：material, items
- 输出：item list, recall, diff report, srs state
- 副作用：写本地 learner-state.json
- 降级：无外部工具时：以对话形式做，Agent 负责出题—等待—核对—评分

**自检问题**

- 我刚才回忆的时候，是真的在看资料，还是只是「认得」？
- 标 ✗ 的条目里，有多少是我以为自己会但其实不会的？

**达标判据**

- 第二轮回忆时 ✗ 数量显著下降
- 回忆速度（每条耗时）逐轮缩短

### 2. 双重编码（`dual-coding`）

*Dual Coding*

**同一个概念用文字 + 图像/图示两套编码各讲一遍，让大脑有两条提取路径。**

- **分类**：记忆巩固
- **循证等级**：medium —— 有一些支持性证据，但结论稳健性中等
- **版本**：0.1.0　**许可**：CC0-1.0

**适用场景**

- ✓ 纯文字记忆效率低
- ✓ 抽象概念（流程/结构/比例）难记

**不适用**

- ✗ 纯技能动作（用 deliberate-practice）
- ✗ 已经能轻松回忆的内容

**入参**

- `concept`（**必填**，string）：要双重编码的单个概念，一个概念一张图，不做大杂烩
- `visual_style`（可选，string），默认 `ASCII 图示或流程箭头`：视觉表现形式，如「流程图」「类比图」「示意图」

**执行步骤**

1. **先写文字版**（`verbal`，约 3 分钟）
   - 做什么：用 100 字以内把这个概念说清楚，包含一个具体例子。
   - 验收线：产出了一段含具体例子的文字说明
   - 产出：verbal
2. **再画图示版**（`visual`，约 5 分钟）
   - 做什么：画一个能表达同样意思的图（流程箭头 / 结构图 / 示意图）。图必须能在不看文字的情况下单独传达核心。
   - 验收线：产出图示；盖住文字后，第三方能说出概念含义
   - 产出：visual
3. **写出连接关系**（`link`，约 2 分钟）
   - 做什么：用一句话说明「图里的哪个部分对应文字里的哪句话」，这是双编码真正起作用的地方。
   - 验收线：映射句覆盖图中所有关键元素，无「大概对应」
   - 产出：mapping
4. **交叉提取测试**（`cross-recall`，约 3 分钟）
   - 做什么：随机给一个元素（文字片段或图中某部分），要求用另一套编码说出来。
   - 验收线：双向提取均成功，≥4/5 项
   - 产出：cross test

**Agent 契约**

- 输入：concept, visual_style
- 输出：verbal, visual, mapping
- 降级：无法绘图时：强制输出结构化文本图（缩进树/编号序列），仍满足「不看文字可传达」的要求

**自检问题**

- 我的图是不是只是把文字抄了一遍？
- 两套编码是真的两条路径，还是同一句话说了两遍？

**达标判据**

- 一周后只看图能复原文字含义
- 只看文字能复原图结构

### 3. 高频短时提取（`retrieval-spread`）

*High-Frequency Short Retrieval*

**每次学完立刻闭卷提取 3 分钟，比之后花一小时复习更有效。**

- **分类**：记忆巩固
- **循证等级**：medium —— 有一些支持性证据，但结论稳健性中等
- **版本**：0.1.0　**许可**：CC0-1.0

**适用场景**

- ✓ 刚学完一段内容
- ✓ 容易「学了等于没学」

**不适用**

- ✗ 需要深度理解时（先用 elaborative-interrogation）

**入参**

- `session`（**必填**，string）：刚学完的内容范围

**执行步骤**

1. **学完立刻合上资料**（`immediate`，约 1 分钟）
   - 做什么：在接触资料后不超过 3 分钟内，切断资料，进行第一次提取。不要「先整理完笔记再提取」。
   - 验收线：距离最后一次阅读材料 ≤ 3 分钟
   - 产出：timestamp
2. **写出一页纸**（`extract`，约 3 分钟）
   - 做什么：不看任何资料，写下你能想起的关于本次内容的一切：概念、逻辑、疑问、例子。
   - 验收线：产出 ≥150 字的无参考资料回忆稿
   - 产出：one-pager
3. **标出想不起的**（`mark-gap`，约 2 分钟）
   - 做什么：对照资料，只用红笔在回忆稿上标出漏掉的部分，不改写内容。
   - 验收线：回忆稿上有明确红色标注，且标注处都有「我以为我会但不会」的自评
   - 产出：annotated p

**Agent 契约**

- 输入：session
- 输出：one-pager
- 降级：无需降级，纯文本可执行

**自检问题**

- 这次提取是 3 分钟内做的吗？
- 标红的地方是不是下次真的考？

**达标判据**

- 一周后提取内容命中率 > 70%

### 4. 间隔重复调度（`spaced-repetition`）

*Spaced Repetition (SM-2)*

**在「快要忘记」的那一刻复习，用最少的总时长换最长的记忆保持。**

- **分类**：记忆巩固
- **循证等级**：high —— 有较强实验证据支持（多项对照研究）
- **版本**：0.1.0　**许可**：CC0-1.0

**适用场景**

- ✓ 需要长期记住大量事实/术语
- ✓ 需要记住代码 API、命令、外语单词等离散项

**不适用**

- ✗ 只考一次的短期突击（用 active-recall 集中刷）
- ✗ 要学会一项技能而非记住一批事实（用 deliberate-practice 或 project-based-learning）

**入参**

- `items`（**必填**，array）：已有 SRS 条目或待入库材料
- `today`（可选，string）：基准日期，默认今天

**执行步骤**

1. **取出今日到期队列**（`due-query`，约 1 分钟）
   - 做什么：扫描本地 learner-state，列出 next_due ≤ today 的条目，按 due 时间正序排列。若为空，进入步骤 5。
   - 验收线：产出了一份有序队列，或显式声明队列为空
   - 产出：due queue
2. **逐条提取**（`review`，约 15 分钟）
   - 做什么：对每条先做主动回忆（不显示答案），然后才核对。禁止直接给答案。
   - 验收线：每条都产生了先回忆后核对的顺序记录
   - 产出：review log
3. **SM-2 重算间隔**（`reschedule`，约 2 分钟）
   - 做什么：按规范 §5 公式更新 ease_factor / interval_days / repetitions / next_due。q<3 时 interval 重置为 1。
   - 验收线：每条的 next_due > today，且 ease_factor ∈ [1.3, 3.0]
   - 产出：updated state
4. **控制单日时长**（`budget`，约 1 分钟）
   - 做什么：统计今日复习总耗时。若超过 20 分钟，把剩余条目的 next_due 顺延一天，不丢条目。
   - 验收线：单日总时长 ≤ 20 分钟，且条目无丢失（顺延数 = 未复习数）
   - 产出：daily summary

**Agent 契约**

- 输入：items, today
- 输出：review log, updated learner-state.json
- 副作用：写本地 learner-state.json
- 降级：无计算工具时：Agent 直接按规范公式手算，并展示中间值供核对

**自检问题**

- 今天复习的条目里，有多少是我在 1 秒内就答出来的（这些可以降频）？
- 有没有条目连续多天 < 3 分（说明当初就不该入库）？

**达标判据**

- 复习队列长度稳定而非无限增长
- 相同总时长下保持率优于集中复习
