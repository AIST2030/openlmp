# 技能习得 · 执行手册（2 个方法）

> 详细步骤、验收线与 Agent 契约。每个方法的 checkpoint 都是**可判定**的，无法判定就说明这一步没做扎实，不要靠感觉通过。

### 1. 刻意练习（`deliberate-practice`）

*Deliberate Practice*

**把大技能拆成刚好超出当前能力一点点的小任务，重复、即时反馈、逐次纠错。**

- **分类**：技能习得
- **循证等级**：high —— 有较强实验证据支持（多项对照研究）
- **版本**：0.1.0　**许可**：CC0-1.0

**适用场景**

- ✓ 练技能（乐器/编程/运动/写作/演讲）
- ✓ 已经重复很多次但没进步

**不适用**

- ✗ 只是要记住知识（用 active-recall）
- ✗ 刚开始学，还没有基本动作

**入参**

- `skill`（**必填**，string）：要刻意练习的具体子技能，如「写 SQL 的 JOIN」「冷启动开场白」
- `current_level`（**必填**，string）：当前水平描述
- `session_min`（可选，integer），默认 `45`：单次练习时长，超时即停（刻意练习要求全程专注不疲劳）

**执行步骤**

1. **找准当前瓶颈**（`diagnose`，约 10 分钟）
   - 做什么：让用户做一次目标技能的完整尝试，Agent 记录：哪一环出错最多。只挑出错最多的那一环，不列清单。
   - 验收线：产出一个明确的最弱环节描述，不是「整体都不行」
   - 产出：bottleneck
2. **设计针对性小练习**（`design-drill`，约 5 分钟）
   - 做什么：针对该瓶颈设计 3–5 个难度递增的小练习，每个练习 2–5 分钟。难度上限：比当前水平难一档。
   - 验收线：练习数 ≥3，且每个都有明确的一句话通过标准
   - 产出：drill list
3. **重复—反馈—归因循环**（`loop`，约 25 分钟）
   - 做什么：每做一个练习：立即给具体反馈（哪里好、哪个动作错了）→ 让用户重做一次 → 记录归因（是知识不足/动作不熟/注意力散）。同一练习最多重做 3 次，超过则说明难度设计有问题，必须降档。
   - 验收线：每个练习至少完成 2 次重做，且 3 次未过的一定被记录为「难度过高」
   - 产出：loop log
4. **提炼可复用规则**（`consolidate`，约 5 分钟）
   - 做什么：把本轮归因中反复出现的那一条，写成一句下次直接可执行的规则（如「换手时先稳肩再转腕」）。
   - 验收线：产出一条动词开头的具体规则，且能对照本次录像验证
   - 产出：one rule

**Agent 契约**

- 输入：skill, current_level, session_min
- 输出：bottleneck, drill list, loop log, one rule
- 副作用：仅写本地文件
- 降级：无法获取真实操作反馈时（无视频/无传感数据）：明确告知用户「缺反馈源」，改为纯自评 + 录像复盘，不假装给了客观反馈

**自检问题**

- 这一小时里，我是在重复已经会的东西，还是在攻最不会的那一点？
- 我拿到的反馈是「再练练」这种废话吗？

**达标判据**

- 同一练习的成功率逐次上升
- 能说出一条以前不知道的规则

### 2. 721 行动学习（`project-based-learning`）

*70-20-10 Action Learning*

**10% 学理论 / 70% 做真实任务 / 20% 复盘，把学习时间强制分配到动手比例上，避免「只学不用」。**

- **分类**：技能习得
- **循证等级**：anecdotal —— 主要来自实践经验与个案，缺少严格实验验证
- **版本**：0.1.0　**许可**：CC0-1.0

**适用场景**

- ✓ 要学职业技能（写作/编程/设计/数据）
- ✓ 读了三个月书没产出
- ✓ 公司内训

**不适用**

- ✗ 纯理论学科（数学定理、法条）
- ✗ 还不会用就想上手（先补最小基础）

**入参**

- `skill`（**必填**，string）：要通过项目练的能力，须有真实可交付的产出物
- `real_task`（**必填**，string）：一个真实存在的、有人要的产出
- `weeks`（可选，integer），默认 `6`：项目周期（周）。周期太短形不成反馈闭环，太长会烂尾

**执行步骤**

1. **先定真实任务**（`task-first`，约 20 分钟）
   - 做什么：先定一个**真实存在、有人要、能在数周内交付**的任务（给朋友做一次 PPT / 上线一个小功能 / 写一篇能发表的文章）。没有真任务的，先找一个人问「你最近需要什么帮助」。
   - 验收线：任务有明确接收方、明确交付物、明确截止日
   - 产出：real task brief
2. **只学任务卡住的部分（10%）**（`plan-10`，约 30 分钟）
   - 做什么：针对任务倒推：现在卡在哪？只学**当前这一步需要的**那部分知识，不要系统学整门课。记录这次学了什么、用了哪一条。
   - 验收线：列出了本次要学的 3–5 个具体问题，且每个都直接对应任务中的某个卡点
   - 产出：targeted syllabus
3. **动手做（70%）**（`do-70`，约 120 分钟）
   - 做什么：直接做，遇到不会就查，查完继续做。**记录每一次「我以为我会但不会」的时刻**——这比做出来的成品更值钱。
   - 验收线：产出了可交付的中间成果；卡点时刻记录 ≥5 条
   - 产出：交付物 + 卡点记录
4. **复盘（20%）**（`review-20`，约 30 分钟）
   - 做什么：回答三问：这次做成的关键动作是什么？卡住的地方暴露了我缺什么？下次遇到同类任务，第一步该做什么？写下一条可执行规则。
   - 验收线：产出一条动词开头的具体规则，且能对照本次产出验证
   - 产出：复盘 + one rule
5. **接下一个更难的任务**（`iterate`，约 10 分钟）
   - 做什么：如果交付被接受，找一个难度高一级、交付物相似但要求更高的任务。重复本流程。难度必须上升，否则是在原地重复。
   - 验收线：新任务的难度确实高于上一轮，且差距不是靠加班补的
   - 产出：next task

**Agent 契约**

- 输入：skill, real_task, weeks
- 输出：real task brief, 复盘
- 副作用：写本地文件
- 降级：用户没有真实任务需求时：Agent 必须提示「先去找一个真实需求」，**禁止**用虚拟练习项目替代——这是本方法的核心机制，替代即失效

**自检问题**

- 这次学的东西，真的被用在交付物上了吗？
- 我记录卡点的时刻，是不是都记得当时在想什么？

**达标判据**

- 每轮都有真实交付物
- 卡点记录逐轮变少
