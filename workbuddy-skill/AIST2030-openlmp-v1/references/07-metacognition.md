# 元认知 · 执行手册（3 个方法）

> 详细步骤、验收线与 Agent 契约。每个方法的 checkpoint 都是**可判定**的，无法判定就说明这一步没做扎实，不要靠感觉通过。

### 1. 今天学到了什么（`diary-question`）

*Daily Learning Questions*

**每天只回答三个问题：我今天真的多会了什么？我怎么知道自己真的会了？明天第一件事做什么？三行，不许写长篇。**

- **分类**：元认知
- **循证等级**：medium —— 有一些支持性证据，但结论稳健性中等
- **版本**：0.1.0　**许可**：CC0-1.0

**适用场景**

- ✓ 每天学完但说不清收获
- ✓ 备考长跑
- ✓ 想提升元认知能力

**不适用**

- ✗ 当天没学任何东西的日子（直接写「今天没学」，这本身也是答案）

**入参**

- `streak`（可选，integer），默认 `21`：目标连续天数

**执行步骤**

1. **三行作答**（`three-lines`，约 5 分钟）
   - 做什么：每天结束时回答且只回答三个问题，每问一行，每行 ≤50字：① 今天我真的多会了什么（不是「看了什么」）② 我怎么验证我真会了③ 明天第一件事做什么。
   - 验收线：三行都写了，且第一行不是「看了 X 课/读了 X 页」这种过程描述
   - 产出：三行日志
2. **给「会了」配证据**（`evidence-line`，约 3 分钟）
   - 做什么：第二行必须是可验证的：能默写出X / 能讲清 Y 的因果 / 做出 Z / 或明确写「其实还没验证」。**禁止只写「感觉懂了」。**
   - 验收线：第二行含一个客观验证动作，或明确承认「未验证」
   - 产出：verification evidence
3. **允许写「没有」**（`honest-gap`，约 2 分钟）
   - 做什么：如果今天确实没学、或学了但什么都没留下，**照实写**。不要为了不断更而编。连续记录的价值来自诚实。
   - 验收线：当日状态与实际一致；未出现「为不断更而编造收获」
   - 产出：当日记录
4. **把明天第一件事挂到未完成项**（`tomorrow-link`，约 3 分钟）
   - 做什么：第三行的「明天第一件事」必须来自：昨天的未完成 / 昨天验证失败的 / 新发现的缺口。禁止填「继续学习 X」这种无指向的话。
   - 验收线：第三行指向一个具体的、有名字的任务
   - 产出：tomorrow anchor
5. **每周扫一遍趋势**（`weekly-scan`，约 15 分钟）
   - 做什么：每周看一次这streak 天的记录，统计：哪一天写的是真收获（第二行有证据）？哪天在空转？**空转的日子有什么共同特征？**
   - 验收线：指出了 ≥2 个空转日的共同特征
   - 产出：weekly pattern

**Agent 契约**

- 输入：streak
- 输出：三行日志
- 副作用：写本地文件
- 降级：Agent 每天主动追问且**只追问这三问**，不展开其他话题；用户答不出第二行时必须追问「怎么验证」

**自检问题**

- 我这周写的「会了」，有几条是真验证过的？
- 明天第一件事，我是不是已经知道要做什么？

**达标判据**

- 第二行含验证动作的比例 >80%
- 连续天数逐周上升

### 2. 学习日志与错因归因（`learning-journal`）

*Learning Journal*

**每天三行：我以为会了什么 / 实际不会什么 / 下次怎么改。把「感觉懂了」变成可追踪记录。**

- **分类**：元认知
- **循证等级**：medium —— 有一些支持性证据，但结论稳健性中等
- **版本**：0.1.0　**许可**：CC0-1.0

**适用场景**

- ✓ 备考期
- ✓ 自学超过一个月没进展
- ✓ 想搞清自己到底卡在哪

**不适用**

- ✗ 只是临时抱佛脚的突击（来不及）

**入参**

- `days`（**必填**，integer），默认 `7`：复盘周期天数

**执行步骤**

1. **每日三行**（`daily`，约 5 分钟）
   - 做什么：每天结束时写三行：①今天我以为我掌握了什么 ②实际做题/回忆时错在哪 ③明天第一件事改什么。要求非常短，不许写长篇。
   - 验收线：连续 days 天均有三行记录，缺任一天必须补写并标注「断更」
   - 产出：journal
2. **错因分类**（`classify`，约 5 分钟）
   - 做什么：把②中的错误归到四类之一：知识缺口 / 审题错 / 记忆提取失败 / 粗心失误。每条必须归到且仅归一类。
   - 验收线：每条错误有且仅有一个类别标签，且四类中至少被使用过两类（否则说明归类过粗）
   - 产出：error taxonomy
3. **找本周主因**（`top-cause`，约 5 分钟）
   - 做什么：统计各类占比，只针对占比最高的一类设计下周干预。若某类占比 <20% 仍为主因，检查是否是归类错误。
   - 验收线：产出一条针对主因的具体干预动作，且该动作可在一周内执行完
   - 产出：intervention
4. **下周回检**（`verify`，约 5 分钟）
   - 做什么：一周后回到步骤 1，检查干预是否有效。主因占比下降则固化；没下降则换类别或换干预方式。
   - 验收线：明确回答「干预有效/无效」，并据此决定保留或更换
   - 产出：verdict

**Agent 契约**

- 输入：days
- 输出：journal, error taxonomy, intervention
- 副作用：写本地日志文件
- 降级：无外部工具时：以对话形式维护，Agent 负责每日提醒与分类统计

**自检问题**

- 这一周我错的主因换了吗，还是同一个错反复犯？
- 我的记录是真写了还是只是列了计划？

**达标判据**

- 主因占比逐周下降
- 断更天数 < 每周 1 天

### 3. 迁移提问训练（`transfer-question`）

*Transfer of Training*

**每学一个概念，立刻问「这在什么别的场景能用」，把知识从课堂搬到真实问题。**

- **分类**：元认知
- **循证等级**：high —— 有较强实验证据支持（多项对照研究）
- **版本**：0.1.0　**许可**：CC0-1.0

**适用场景**

- ✓ 考试能做但实际不会用
- ✓ 学了理论不会落地
- ✓ 准备面试/实操

**不适用**

- ✗ 纯事实记忆阶段（还没到迁移环节）

**入参**

- `concept`（**必填**，string）：要检验迁移能力的目标概念
- `domains`（可选，array），默认 `['工作', '生活', '另一个学科']`：要迁移到哪些不同的应用领域（至少 2 个，跨领域才叫迁移）

**执行步骤**

1. **找一个真实场景**（`real-case`，约 4 分钟）
   - 做什么：为该概念指出一个你生活/工作中真实存在的具体场景，必须是你遇到过或能核实的，禁止编造。
   - 验收线：场景描述具体到可判断真假（含人物、时间、约束）
   - 产出：scenario
2. **画出对应关系**（`map`，约 6 分钟）
   - 做什么：逐一对应：真实场景中的哪个要素 ↔ 理论中的哪个概念。对不上的部分明确写「理论在这里不适用」。
   - 验收线：至少指出一个「理论不适用」或「需要修正」的边界
   - 产出：mapping
3. **跨领域移植**（`cross-domain`，约 6 分钟）
   - 做什么：把这个概念强行用到 domains 中的另一个领域，写出一个具体的类比推理链，并指出类比在哪里会失效。
   - 验收线：类比链 ≥3 步，且明确标出失效边界
   - 产出：analogy
4. **落到一个待解决的真问题上**（`action`，约 8 分钟）
   - 做什么：找一个你当前真实存在的待解决问题，用这个概念重新分析一遍，给出可执行的改变。
   - 验收线：产出了一条明天就能做的具体动作，不是「要多练习」这类空话
   - 产出：action

**Agent 契约**

- 输入：concept, domains
- 输出：scenario, mapping, analogy, action
- 降级：Agent 不得虚构用户经历：若用户说不出真实场景，必须引导提问而非代为编造

**自检问题**

- 我举的场景是真的发生过，还是我编的？
- 我说的迁移是换个说法，还是真的能解决不同的问题？

**达标判据**

- 能主动举出至少一个教科书没写的应用
- 真问题上有可观测的改变
