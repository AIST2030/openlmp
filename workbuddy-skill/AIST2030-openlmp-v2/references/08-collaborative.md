# 协作学习 · 执行手册（4 个方法）

> 详细步骤、验收线与 Agent 契约。每个方法的 checkpoint 都是**可判定**的，无法判定就说明这一步没做扎实，不要靠感觉通过。

### 1. 结对学习（`pair-learning`）

*Pair Learning*

**两个人学同一件事，每周交换一次「出题人」和「答题人」角色。强迫你换视角——讲解别人的卡点，比自己学更快暴露盲区。**

- **分类**：协作学习
- **循证等级**：medium —— 有一些支持性证据，但结论稳健性中等
- **版本**：0.1.0　**许可**：CC0-1.0

**适用场景**

- ✓ 自学容易走偏没人纠
- ✓ 想快速上手新技能
- ✓ 备考互相出题

**不适用**

- ✗ 找不到合适的人
- ✗ 内容涉及必须独立完成的能力（如写作风格）

**入参**

- `partner`（**必填**，string）：搭档，需大致同水平
- `topic`（**必填**，string）：结对共同攻克的主题，需双方都具备基础才能讨论

**执行步骤**

1. **定好角色轮换**（`role-rotate`，约 5 分钟）
   - 做什么：约定每周轮换：A 讲解 B 提问，B 提问 A 讲解。**必须轮换**——单方面讲解的人成长最慢，因为他没被问到盲区。
   - 验收线：产出轮换表，且本次谁讲解谁提问已明确
   - 产出：rotation
2. **讲解人的 5 分钟**（`teach-back`，约 6 分钟）
   - 做什么：讲解人用5 分钟讲清本周学的核心，**不许念稿子**，不许看笔记。
   - 验收线：讲解全程不看材料；且包含至少一个具体例子
   - 产出：teach-back
3. **提问人只问「为什么」**（`questioner`，约 6 分钟）
   - 做什么：提问人**不许问「是什么」**（那是复述），只许问「为什么」「如果 X 变了会怎样」「你说的这个和 Y 矛盾吗」。每问一个就判断：答案里有没有逻辑跳跃？
   - 验收线：提问 ≥3 个且全部是「为什么/如果」类；至少找出 1 处逻辑跳跃或含糊处
   - 产出：questions + gaps
4. **讲解人当场补漏**（`explain-gap`，约 8 分钟）
   - 做什么：被问住的地方，当场去查，或明确说「这个我不知道，记下来」。**不许糊过去。**
   - 验收线：所有被问住的地方都有结论（查到或明确未知）；无糊弄
   - 产出：gap closure
5. **反向出题**（`swap-question`，约 12 分钟）
   - 做什么：由提问人出 3 道题给讲解人做。**做不出来正是本环节的目的**——不是测验，是找盲区。
   - 验收线：出题 3 道且难度对等；做错/做不出处已记录进错题本
   - 产出：test
6. **记录不对称**（`symmetry-check`，约 5 分钟）
   - 做什么：记录：谁被问住得更少？连续两周都是同一个人，说明另一个人提问不够狠，需要换策略（改成互相出题）。
   - 验收线：给出了「谁被问住更多」的事实判断，并据此决定是否调整方式
   - 产出：symmetry note

**Agent 契约**

- 输入：partner, topic
- 输出：questions + gaps
- 降级：无搭档时：Agent 扮演提问人，且**必须真的问出尖锐问题**，不许敷衍地说「很好，继续」。扮演讲解人时 Agent **不得**代替用户作答

**自检问题**

- 这周我是讲解多还是提问多？我是不是一直只做擅长的那个？
- 搭档指出的问题，是我没意识到的还是不想承认的？

**达标判据**

- 双方被问住的次数差距 <2倍
- 每次都能说出至少 1 个自己没意识到的盲区

### 2. 同伴教学法（`peer-instruction`）

*Peer Instruction*

**先抛一个概念题让大家各自投票，再与同伴讨论理由后二次投票，用观点碰撞把误解暴露并修正。**

- **分类**：协作学习
- **循证等级**：medium —— 有一些支持性证据，但结论稳健性中等
- **版本**：0.1.0　**许可**：CC0-1.0

**适用场景**

- ✓ 小组课的难点概念
- ✓ 自己拿不准的理解
- ✓ 想借他人视角发现盲区

**不适用**

- ✗ 无同伴可讨论时（可用 Agent 模拟反方）

**入参**

- `concept`（**必填**，string）：要通过同伴教学攻克的概念

**执行步骤**

1. **出一道概念题**（`pose`，约 8 分钟）
   - 做什么：针对该概念出一道有迷惑选项的概念题，选项覆盖常见误解，先不给答案。
   - 验收线：题目已出且含迷惑选项；且覆盖至少 1 个常见误解
   - 产出：概念题
2. **各自独立投票**（`vote1`，约 4 分钟）
   - 做什么：每人先独立作答并记下所选与一句理由，此时不得讨论。
   - 验收线：每人都有独立投票记录及理由；且投票期间无讨论
   - 产出：首轮投票
3. **结对说服**（`discuss`，约 10 分钟）
   - 做什么：与同伴就不同选择讨论，各自陈述理由说服对方，记录被说服或坚持的原因。
   - 验收线：每人记录了讨论后是否改变选择及原因
   - 产出：讨论记录
4. **二次投票并揭晓**（`vote2`，约 8 分钟）
   - 做什么：再次独立投票，然后公布答案与解析，重点讲正确项为何对、错误项错在哪。
   - 验收线：完成二轮投票；且解析覆盖正确项与各错误项的错因
   - 产出：二轮投票与解析
   - 不通过回到：`pose`

**Agent 契约**

- 输入：concept
- 输出：概念题, 两轮投票, 解析
- 副作用：仅写本地文件
- 降级：单人时：让 Agent 扮演持不同观点的同学进行辩论

**自检问题**

- 首轮我是不是凭感觉选的？
- 被说服是因为想清楚了，还是碍于情面？

**达标判据**

- 二轮正确率高于首轮
- 能说出每个错误选项错在哪

### 3. 同伴互评（`peer-review-loop`）

*Peer Review Loop*

**互相按同一份评分表批改对方的作品，写清楚扣分依据；批改别人的过程反过来提升自己的判断力。**

- **分类**：协作学习
- **循证等级**：medium —— 有一些支持性证据，但结论稳健性中等
- **版本**：0.1.0　**许可**：CC0-1.0

**适用场景**

- ✓ 写作或代码需要外部视角
- ✓ 小组作业互评
- ✓ 想练出评审眼光

**不适用**

- ✗ 作品涉密或不宜示人

**入参**

- `work`（**必填**，string）：待互评的作品
- `criteria`（可选，integer），默认 `4`：评分维度数量

**执行步骤**

1. **先统一评分表**（`rubric`，约 10 分钟）
   - 做什么：共同确定 4 个评分维度及各自的合格标准，写成一页量规。评分前必须完成。
   - 验收线：量规含指定数量维度；且每维有可核对的合格标准
   - 产出：共用量规
2. **各自独立批改**（`review`，约 20 分钟）
   - 做什么：每人按量规给对方作品打分，每条扣分必须写明对应作品的具体位置。
   - 验收线：每位参与者都有评分记录；且每条扣分附了作品位置引用
   - 产出：评分记录
3. **对差异项讨论**（`compare`，约 12 分钟）
   - 做什么：把两人评分不一致的项挑出来逐条讨论，直到对量规理解一致。
   - 验收线：列出了不一致项；且每项给出了统一后的判定
   - 产出：差异讨论结论
4. **按反馈改稿**（`revise`，约 20 分钟）
   - 做什么：作者按收到的反馈逐条修改，标注改了哪里、为什么这么改。
   - 验收线：每条反馈都有对应修改；且修改处注明了理由
   - 产出：修订稿
   - 不通过回到：`review`

**Agent 契约**

- 输入：work, criteria
- 输出：评分记录, 差异结论, 修订稿
- 副作用：仅写本地文件
- 降级：无人互评时：Agent 按量规逐条批注并说明依据

**自检问题**

- 我的扣分能指出具体位置吗？
- 评分不一致时，是量规模糊还是我理解偏了？

**达标判据**

- 两人评分差 ≤ 1 分（总分制）
- 反馈条目均被处理

### 4. 互讲圈（`teach-back-circle`）

*Teach-Back Circle*

**几个人轮流讲同一个知识点，每人讲完由其他人复述并挑错，靠同伴的压力把盲区挤出来。**

- **分类**：协作学习
- **循证等级**：medium —— 有一些支持性证据，但结论稳健性中等
- **版本**：0.1.0　**许可**：CC0-1.0

**适用场景**

- ✓ 小组复习备考
- ✓ 团队知识对齐
- ✓ 自己讲容易自我欺骗时

**不适用**

- ✗ 独自学习或时间极紧

**入参**

- `topic`（**必填**，string）：本轮要互讲的知识点
- `people`（可选，integer），默认 `3`：参与人数

**执行步骤**

1. **一人主讲**（`teach`，约 12 分钟）
   - 做什么：指定一人主讲该知识点，其他人只听不打断，记录听不懂的地方。
   - 验收线：主讲完成；且听众记录了听不懂处
   - 产出：讲解与疑问清单
2. **听众复述**（`echo`，约 6 分钟）
   - 做什么：由一名听众不看任何资料复述刚才的内容，主讲不得提示。
   - 验收线：复述完成；且复述期间主讲未给提示
   - 产出：复述记录
3. **集体挑错**（`challenge`，约 8 分钟）
   - 做什么：所有人指出复述里遗漏或说错的地方，逐条记下。只记录事实偏差，不争论措辞。
   - 验收线：列出了遗漏/错误条目；且每条为可核对的事实偏差
   - 产出：错题清单
4. **换人重讲**（`rotate`，约 12 分钟）
   - 做什么：换下一个人主讲同一知识点，重点补上刚才的错题清单。讲完再复盘一次。
   - 验收线：换人后重讲覆盖了错题清单；且复盘给出了剩余问题
   - 产出：二轮讲解与复盘
   - 不通过回到：`echo`

**Agent 契约**

- 输入：topic, people
- 输出：讲解记录, 复述记录, 错题清单
- 副作用：仅写本地文件
- 降级：单人时：让 Agent 扮演听众，负责复述与挑错

**自检问题**

- 我挑出来的错是事实偏差，还是只是说法不同？
- 换人讲之后，第一轮的问题真的解决了吗？

**达标判据**

- 二轮复述遗漏数少于首轮
- 同一盲区不再复现
