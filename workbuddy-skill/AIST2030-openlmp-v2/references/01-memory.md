# 记忆巩固 · 执行手册（15 个方法）

> 详细步骤、验收线与 Agent 契约。每个方法的 checkpoint 都是**可判定**的，无法判定就说明这一步没做扎实，不要靠感觉通过。

### 1. 主动回忆练习（`active-recall`）

*Active Recall*

**关掉资料，凭记忆主动提取信息，把「看着眼熟」换成「真的想得出」。**

- **分类**：记忆巩固
- **循证等级**：high —— 有较强实验证据支持（多项对照研究）
- **版本**：0.1.0　**许可**：CC0-1.0

**适用场景**

- ✓ 感觉记住了但考不出来
- ✓ 背了就忘
- ✓ 考前冲刺

**不适用**

- ✗ 第一次接触全新材料（此时还没东西可提取）

**入参**

- `material`（**必填**，string）：要记住的材料（关键词表/步骤/公式/问答对）
- `items`（可选，integer），默认 `10`：本轮条目数上限

**执行步骤**

1. **切成可独立提取的条目**（`chunk`，约 5 分钟）
   - 做什么：把材料拆成互不依赖的最小单元（一个术语、一组步骤、一个问答对）。每条控制在 20 秒内能说完。
   - 验收线：条目数 ≥ 3，且每条都不需要看其他条目才能回答
   - 产出：item list
2. **合上资料，空白输出**（`blank-sheet`，约 8 分钟）
   - 做什么：严禁 Agent 先展示答案。让 Agent 或用户在不看原资料的情况下，把每条内容写出来。允许写不出，但不允许对照修改。
   - 验收线：产出了一份明确标记了「想不出」的完整回忆稿；回忆稿在核对前不可修改
   - 产出：blank-sheet recall
3. **对照差异**（`diff`，约 5 分钟）
   - 做什么：现在才打开原资料，逐条标：✓ 全对 / △ 漏了关键点 / ✗ 完全错。
   - 验收线：每一条都有 ✓/△/✗ 标记，且 △ 行的「漏了什么」被具体写出
   - 产出：diff report
4. **给分并写入调度**（`score`，约 3 分钟）
   - 做什么：为每条给 self_score（0=完全想不出，5=毫不费力）。把 ✗ 和 △ 的条目写入复习队列，next_due 由 SM-2 计算。
   - 验收线：全部条目都有 0-5 的分数，且所有 ≤4 分的条目都有 next_due 时间
   - 产出：SRS entries

**Agent 契约**

- 输入：material, items
- 输出：item list, recall, diff report, srs state
- 副作用：写本地 learner-state.json
- 降级：无外部工具时：以对话形式做，Agent 负责出题—等待—核对—评分

**自检问题**

- 我刚才回忆的时候，是真的在看资料，还是只是「认得」？
- 标 ✗ 的条目里，有多少是我以为自己会但其实不会的？

**达标判据**

- 第二轮回忆时 ✗ 数量显著下降
- 回忆速度（每条耗时）逐轮缩短

### 2. 回针缝复习（`backstitch-review`）

*Backstitch Review*

**像回针缝一样，每学新的一段就回头缝一针复习前面，边前进边回缝，让旧内容不脱线。**

- **分类**：记忆巩固
- **循证等级**：anecdotal —— 主要来自实践经验与个案，缺少严格实验验证
- **版本**：0.1.0　**许可**：CC0-1.0

**适用场景**

- ✓ 连续学多章，前面开始忘
- ✓ 长课程或长文阅读
- ✓ 想边学边保温

**不适用**

- ✗ 章节相互独立、无需前后关联时（单独安排复习更省）

**入参**

- `scope`（**必填**，string）：要连续推进的学习范围

**执行步骤**

1. **切成针脚段**（`segment`，约 4 分钟）
   - 做什么：把范围切成若干小段，每段是一个针脚；定下每学完一段就回缝前几段的规则。
   - 验收线：范围被切成至少 5 段；且写明了回缝规则
   - 产出：分段与回缝规则
2. **学新段**（`advance`，约 20 分钟）
   - 做什么：按顺序学当前这一段，学完在本段末尾写下三句话要点。
   - 验收线：当前段已学完；且写下了三句话要点
   - 产出：本段要点
3. **回缝前几段**（`backstitch`，约 8 分钟）
   - 做什么：不看书，只凭记忆复述前两段的要点，卡住的标注；然后才继续下一段。
   - 验收线：前两段要点被复述；且卡住处被标注
   - 产出：回缝记录
4. **锁紧断线段**（`tighten`，约 6 分钟）
   - 做什么：每完成 5 段，把所有标注过的断线段集中重缝一遍，再继续前进。
   - 验收线：每 5 段后集中重缝一次；且重缝覆盖了全部标注段
   - 产出：重缝结果
   - 不通过回到：`backstitch`

**Agent 契约**

- 输入：scope
- 输出：本段要点, 回缝记录
- 副作用：仅写本地文件
- 降级：无工具时：每段末尾默述前两段要点

**自检问题**

- 我是真在回缝，还是只顾往前赶？
- 回缝时卡住的，是当时没懂还是真忘了？

**达标判据**

- 回缝复述成功率随针脚保持稳定
- 断线段经重缝后减少

### 3. 组块化（`chunking`）

*Chunking*

**把零散信息按意义打包成少数几个块，绕开短时记忆的容量上限。**

- **分类**：记忆巩固
- **循证等级**：medium —— 有一些支持性证据，但结论稳健性中等
- **版本**：0.1.0　**许可**：CC0-1.0

**适用场景**

- ✓ 记号码/清单/长串步骤
- ✓ 信息碎且多
- ✓ 背单词或术语表

**不适用**

- ✗ 材料本身已成体系（直接建结构更快）

**入参**

- `material`（**必填**，string）：需要压缩记忆的零散材料
- `chunk_size`（可选，integer），默认 `4`：每个块内的条目上限

**执行步骤**

1. **按意义分组**（`group`，约 8 分钟）
   - 做什么：把材料按语义/用途/时间分成若干组，每组不超过 chunk_size 条。给每组起一个短标题。
   - 验收线：所有条目都归入了某一组，且每组都有标题、条数 ≤ chunk_size
   - 产出：分组表
2. **提炼组标签**（`label`，约 5 分钟）
   - 做什么：为每组造一个能提示全部内容的短标签（≤6 字），越有画面感越好。
   - 验收线：每组都有标签，且标签长度 ≤6 字
   - 产出：标签清单
3. **只凭标签还原**（`recall`，约 8 分钟）
   - 做什么：只看标签清单，逐组写出全部原始条目。写不出就留空，不要翻原文。
   - 验收线：产出了一份按标签组织的还原稿，且空项被显式保留
   - 产出：还原稿
4. **核对并压缩**（`diff`，约 7 分钟）
   - 做什么：对照原文统计每组漏了几条。把漏得多的组再拆小，直到每组还原都能全对。
   - 验收线：记录了每组漏条数；对漏条数 >0 的组给出了新的拆分方案
   - 产出：压缩方案与漏条统计
   - 不通过回到：`group`

**Agent 契约**

- 输入：material, chunk_size
- 输出：分组表, 标签清单, 还原结果
- 副作用：仅写本地文件
- 降级：无工具时：对话中完成分组、贴标签与还原核对

**自检问题**

- 我的分组依据是意义，还是仅仅因为凑在一起？
- 标签能不能真的提示出全部内容？

**达标判据**

- 凭标签还原的完整率逐轮上升
- 所需组数稳定不再增加

### 4. 必要难度（`desirable-difficulty`）

*Desirable Difficulty*

**刻意把学习搞得「稍微费劲一点」——慢一点、隔久一点、换个形式，当下更累但记得更牢。**

- **分类**：记忆巩固
- **循证等级**：medium —— 有一些支持性证据，但结论稳健性中等
- **版本**：0.1.0　**许可**：CC0-1.0

**适用场景**

- ✓ 学得太顺反而记不住
- ✓ 一遍遍看觉得都会
- ✓ 想提升长期保持率

**不适用**

- ✗ 时间极紧的临时突击（此时需要的是效率不是保持率）

**入参**

- `material`（**必填**，string）：当前觉得「已经会了」的材料

**执行步骤**

1. **确认是真会还是看着眼熟**（`measure`，约 5 分钟）
   - 做什么：不参考资料，把材料要点写出来，再逐条对照。把「以为会其实不会」的条目标出来。
   - 验收线：产出了一份在核对前完成的默写稿，且标出了不相符的条目
   - 产出：对照差异表
2. **加一层难度**（`raise`，约 8 分钟）
   - 做什么：从以下选一项施加：① 延迟 1 天再复习 ② 换成另一种题型表述 ③ 打乱顺序。每次只加一项。
   - 验收线：明确写明了施加的是①②③中的哪一项，且只施加了一项
   - 产出：难度施加记录
3. **隔天复测**（`retest`，约 8 分钟）
   - 做什么：至少间隔 24 小时后，不看资料重做一遍上次标出的条目，记录正确率。
   - 验收线：复测与首次默写间隔 ≥ 24 小时，且记录了正确条目数与总条目数
   - 产出：复测正确率
   - 不通过回到：`raise`

**Agent 契约**

- 输入：material
- 输出：对照差异表, 复测正确率
- 副作用：仅写本地文件
- 降级：无工具时：口头默写与核对，不需要外部资料

**自检问题**

- 我选的「更费劲」是真的费劲，还是只是更花时间？
- 隔天复测的正确率比之前高了吗？

**达标判据**

- 隔天复测正确率高于当天即时复测
- 所需提示次数减少

### 5. 双重编码（`dual-coding`）

*Dual Coding*

**同一个概念用文字 + 图像/图示两套编码各讲一遍，让大脑有两条提取路径。**

- **分类**：记忆巩固
- **循证等级**：medium —— 有一些支持性证据，但结论稳健性中等
- **版本**：0.1.0　**许可**：CC0-1.0

**适用场景**

- ✓ 纯文字记忆效率低
- ✓ 抽象概念（流程/结构/比例）难记

**不适用**

- ✗ 纯技能动作（用 deliberate-practice）
- ✗ 已经能轻松回忆的内容

**入参**

- `concept`（**必填**，string）：要双重编码的单个概念，一个概念一张图，不做大杂烩
- `visual_style`（可选，string），默认 `ASCII 图示或流程箭头`：视觉表现形式，如「流程图」「类比图」「示意图」

**执行步骤**

1. **先写文字版**（`verbal`，约 3 分钟）
   - 做什么：用 100 字以内把这个概念说清楚，包含一个具体例子。
   - 验收线：产出了一段含具体例子的文字说明
   - 产出：verbal
2. **再画图示版**（`visual`，约 5 分钟）
   - 做什么：画一个能表达同样意思的图（流程箭头 / 结构图 / 示意图）。图必须能在不看文字的情况下单独传达核心。
   - 验收线：产出图示；盖住文字后，第三方能说出概念含义
   - 产出：visual
3. **写出连接关系**（`link`，约 2 分钟）
   - 做什么：用一句话说明「图里的哪个部分对应文字里的哪句话」，这是双编码真正起作用的地方。
   - 验收线：映射句覆盖图中所有关键元素，无「大概对应」
   - 产出：mapping
4. **交叉提取测试**（`cross-recall`，约 3 分钟）
   - 做什么：随机给一个元素（文字片段或图中某部分），要求用另一套编码说出来。
   - 验收线：双向提取均成功，≥4/5 项
   - 产出：cross test

**Agent 契约**

- 输入：concept, visual_style
- 输出：verbal, visual, mapping
- 降级：无法绘图时：强制输出结构化文本图（缩进树/编号序列），仍满足「不看文字可传达」的要求

**自检问题**

- 我的图是不是只是把文字抄了一遍？
- 两套编码是真的两条路径，还是同一句话说了两遍？

**达标判据**

- 一周后只看图能复原文字含义
- 只看文字能复原图结构

### 6. 精细复述（`elaborative-rehearsal`）

*Elaborative Rehearsal*

**不满足于把信息念很多遍，而是给每条信息接上一个意思、一个例子、一个画面。**

- **分类**：记忆巩固
- **循证等级**：medium —— 有一些支持性证据，但结论稳健性中等
- **版本**：0.1.0　**许可**：CC0-1.0

**适用场景**

- ✓ 反复念但记不住
- ✓ 背定义、背单词
- ✓ 信息孤立无关联

**不适用**

- ✗ 只需短期记住马上就能丢的内容

**入参**

- `item`（**必填**，string）：要记住的那一条信息

**执行步骤**

1. **问它为什么成立**（`ask-why`，约 4 分钟）
   - 做什么：针对这条信息，写出一个「因为……」的理由。写不出就明确记录「原因不明，待查」。
   - 验收线：产出了一个以「因为」开头的完整句子，或一条明确的待查记录
   - 产出：理由句
2. **接一个已知事物**（`hook`，约 6 分钟）
   - 做什么：找一个你已经熟悉的东西跟它做关联，写成一句「它就像……，只不过……」。
   - 验收线：产出了一句含「就像」和「只不过」的类比句
   - 产出：类比句
3. **放一个具体场景**（`scene`，约 5 分钟）
   - 做什么：想一个这条信息真正会被用到的具体场景，写出场景里发生了什么、谁在做、结果如何。
   - 验收线：场景描述里同时含有人物、动作与结果三个要素
   - 产出：场景描述
4. **不看原文复述**（`retrieve`，约 5 分钟）
   - 做什么：合上资料，把这三层（理由/类比/场景）各说一遍。说不全的部分标出来，回到对应步骤重做。
   - 验收线：三层内容都被复述且缺失项被标出；缺失项已指定回退到哪一步
   - 产出：复述结果
   - 不通过回到：`ask-why`

**Agent 契约**

- 输入：item
- 输出：理由句, 类比句, 场景描述
- 副作用：仅写本地文件
- 降级：无工具时：口头完成三层加工

**自检问题**

- 我是真的给它加了意思，还是只是多念了几遍？
- 这条信息现在挂在我的哪块已有知识上？

**达标判据**

- 不看资料能说出理由、类比与场景三层
- 三天后仍能回忆出场景

### 7. 情绪联动记忆（`emotion-anchoring`）

*Emotion Anchoring*

**把要记的内容主动绑到一个带情绪的个人场景上，用情绪强度给记忆加挂钉，事后靠场景回捞内容。**

- **分类**：记忆巩固
- **循证等级**：anecdotal —— 主要来自实践经验与个案，缺少严格实验验证
- **版本**：0.1.0　**许可**：CC0-1.0

**适用场景**

- ✓ 记枯燥的清单或术语
- ✓ 需要长期记住的少量关键信息
- ✓ 常规方法记不牢时

**不适用**

- ✗ 需精确复述的法律条文或数据（情绪联想易引入偏差）

**入参**

- `items`（**必填**，string）：要记的内容清单

**执行步骤**

1. **选锚点场景**（`pick`，约 5 分钟）
   - 做什么：回忆几个自己情绪强烈的真实场景，如某次惊喜、尴尬、紧张，各起一个名字备用。
   - 验收线：列出了至少 3 个带情绪的锚点场景；且每个有名字
   - 产出：锚点场景库
2. **逐条绑定**（`bind`，约 12 分钟）
   - 做什么：把每条内容塞进一个锚点场景，写成一句这个场景里发生了什么、如何体现该内容。
   - 验收线：每条内容都绑定到一个场景；且写出了场景与内容的关联句
   - 产出：绑定清单
3. **靠场景回捞**（`recall`，约 8 分钟）
   - 做什么：只看锚点场景名，回捞对应内容；回捞不出的条目重绑到更强的场景。
   - 验收线：每个场景都完成了一次回捞；回捞失败项被重绑
   - 产出：回捞记录
4. **隔时重测**（`decay`，约 6 分钟）
   - 做什么：隔一两天重测，统计仍靠场景才想起的条目，逐步练习脱离场景直接回忆。
   - 验收线：完成了隔时重测；且记录了脱离场景可直接回忆的比例
   - 产出：重测结果
   - 不通过回到：`bind`

**Agent 契约**

- 输入：items
- 输出：绑定清单, 回捞记录
- 副作用：仅写本地文件
- 降级：无工具时：口头编场景并复述

**自检问题**

- 我绑的场景是真有情绪，还是硬编的？
- 我是在靠场景回捞，还是直接记住了内容？

**达标判据**

- 初期靠场景回捞成功率高于无锚点时
- 逐步提高脱离场景直接回忆的比例

### 8. 交错练习（`interleaving`）

*Interleaving*

**把同一科的多种题型混着练，逼大脑每次先判断「该用哪招」，而不是无脑套上一个刚练的模式。**

- **分类**：记忆巩固
- **循证等级**：high —— 有较强实验证据支持（多项对照研究）
- **版本**：0.1.0　**许可**：CC0-1.0

**适用场景**

- ✓ 分章节练都挺顺、一综合就不会
- ✓ 公式/方法长得像容易混
- ✓ 数学或编程刷题

**不适用**

- ✗ 完全零基础的新题型（先分块练熟再交错）

**入参**

- `topic`（**必填**，string）：本次交错练习覆盖的范围，如「求极值」
- `rounds`（可选，integer），默认 `12`：题目总道数

**执行步骤**

1. **列出待混题型**（`inventory`，约 4 分钟）
   - 做什么：把这个范围里会考的题型写成清单，每种一句话说明「看到什么特征就该用它」。至少 3 种。
   - 验收线：题型清单 ≥ 3 种，且每种都附了一条可判别的识别特征
   - 产出：题型清单
2. **打乱出题**（`shuffle`，约 20 分钟）
   - 做什么：按清单混合出题，相邻两题不出现同一类型。让 Agent 一次只给一题，做完再给下一题。
   - 验收线：题序中不存在相邻同型；作答期间未展示答案
   - 产出：混合题组与作答记录
3. **归因错误类型**（`diagnose`，约 6 分钟）
   - 做什么：逐题标注错因：① 选错方法 ② 方法对但算错 ③ 概念不清。只标不改正。
   - 验收线：每道错题都归入①②③之一，且未混入评价性描述
   - 产出：错因标注表
4. **只补最集中的一类**（`repair`，约 10 分钟）
   - 做什么：统计三类各占多少，挑数量最多的那一类专项重练 5 题，其余两类先不动。
   - 验收线：专项重练题数 = 5，且全部属于被选中的那一类
   - 产出：专项重练结果
   - 不通过回到：`shuffle`

**Agent 契约**

- 输入：topic, rounds
- 输出：题型清单, 作答记录, 错因标注表
- 副作用：仅写本地文件
- 降级：无工具时：对话式一问一答出题，不联网检索

**自检问题**

- 我做错的是因为不知道用哪个方法，还是知道用哪个但做错了？
- 混着练的时候，我有没有先停顿判断题型，还是直接开做？

**达标判据**

- 综合卷的错题里「选错方法」占比下降
- 相邻同型题不再连错

### 9. 记忆宫殿（`method-of-loci`）

*Method of Loci*

**把要记的东西挂在你熟得闭眼都能走的空间路线上，用空间顺序当索引，回想时沿路走一遍。**

- **分类**：记忆巩固
- **循证等级**：medium —— 有一些支持性证据，但结论稳健性中等
- **版本**：0.1.0　**许可**：CC0-1.0

**适用场景**

- ✓ 要背一长串有序内容
- ✓ 演讲提纲、清单、流程
- ✓ 视觉记忆好的人

**不适用**

- ✗ 内容之间有强逻辑关联（用概念图更好）

**入参**

- `items`（**必填**，string）：要记的条目，用逗号或换行分隔
- `route`（可选，string），默认 `自家从门口到卧室的路线`：用作索引的熟悉空间

**执行步骤**

1. **定路线和桩点**（`route`，约 5 分钟）
   - 做什么：选一条你极其熟悉的路线，按顺序数出与条目数相同的固定位置（如鞋柜→沙发→餐桌…）。把位置写成编号清单。
   - 验收线：桩点数量 ≥ 条目数量，且每个桩点都是可独立指认的固定位置
   - 产出：桩点编号清单
2. **挂上夸张图像**（`encode`，约 15 分钟）
   - 做什么：为每条内容造一个视觉夸张、动作荒诞的图像，放到对应桩点上。图像越离谱越好记。
   - 验收线：每个桩点都配了一个含动作的画面描述，且描述里含具体名词与动词
   - 产出：图像-桩点对照表
3. **沿路走一遍回忆**（`walk`，约 6 分钟）
   - 做什么：不看书，按桩点顺序逐个说出对应内容。卡住的桩点标红，不跳过去。
   - 验收线：覆盖全部桩点一次；卡壳桩点被显式标出且数量已统计
   - 产出：回忆结果表
4. **只重做卡壳桩点**（`strengthen`，约 8 分钟）
   - 做什么：把标红桩点的图像改得更夸张，重新走一遍。至少连续 2 次全对为止。
   - 验收线：连续 2 轮回忆中标红桩点数 = 0
   - 产出：强化结果
   - 不通过回到：`encode`

**Agent 契约**

- 输入：items, route
- 输出：桩点清单, 图像对照表, 回忆结果表
- 副作用：仅写本地文件
- 降级：无工具时：纯文字描述桩点与图像，靠对话完成走桩

**自检问题**

- 我的图像够不够具体，能不能「看见」它在动？
- 卡壳的位置是固定几个，还是每次都不一样？

**达标判据**

- 按序回忆时能一次不卡走完全程
- 一周后仍能按序说出 ≥80% 的条目

### 10. 谐音联想法（`mnemonic-association`）

*Mnemonic Association*

**把要记的无意义材料用谐音、图像、故事强行挂到熟悉事物上，化抽象为具体、化无序为有序。**

- **分类**：记忆巩固
- **循证等级**：anecdotal —— 主要来自实践经验与个案，缺少严格实验验证
- **版本**：0.1.0　**许可**：CC0-1.0

**适用场景**

- ✓ 记无意义材料，如术语、编号、词表
- ✓ 纯死记总忘
- ✓ 需要快速记一批条目

**不适用**

- ✗ 需要精确用法的复杂概念（联想只作钩子，会引入偏差）

**入参**

- `items`（**必填**，string）：要记的条目清单

**执行步骤**

1. **列出待记条目**（`list`，约 5 分钟）
   - 做什么：把要记的条目列成清单，每条限定为一个最小记忆单元。
   - 验收线：清单条目至少 5 条；且每条为最小记忆单元
   - 产出：待记清单
2. **逐条造联想**（`hook`，约 15 分钟）
   - 做什么：为每条造一个谐音或形象联想，写成一个具体画面或小故事，越夸张越好。
   - 验收线：每条都配了一个具体画面或故事；且无空白联想的条目
   - 产出：联想表
3. **复述联想**（`encode`，约 8 分钟）
   - 做什么：盖住原条目，只看联想表复述对应内容，卡住的强化那个画面。
   - 验收线：每条都经过一次据联想复述；且卡住条目被强化
   - 产出：复述结果
4. **隔时重测**（`decay`，约 8 分钟）
   - 做什么：隔一段时间，如当晚和隔天，重测并统计仍靠联想才想起的条目，淘汰想不起来的联想并重造。
   - 验收线：完成了隔时重测；且想不起来的联想被重造
   - 产出：重测与迭代
   - 不通过回到：`hook`

**Agent 契约**

- 输入：items
- 输出：联想表, 重测结果
- 副作用：仅写本地文件
- 降级：无工具时：口头编故事并复述

**自检问题**

- 我的联想是真有画面，还是只是换个词？
- 隔天后，是联想在帮我还是我已直接记住了？

**达标判据**

- 隔时重测保持率高于纯死记
- 多数条目最终脱离联想也能想起

### 11. 高频短时提取（`retrieval-spread`）

*High-Frequency Short Retrieval*

**每次学完立刻闭卷提取 3 分钟，比之后花一小时复习更有效。**

- **分类**：记忆巩固
- **循证等级**：medium —— 有一些支持性证据，但结论稳健性中等
- **版本**：0.1.0　**许可**：CC0-1.0

**适用场景**

- ✓ 刚学完一段内容
- ✓ 容易「学了等于没学」

**不适用**

- ✗ 需要深度理解时（先用 elaborative-interrogation）

**入参**

- `session`（**必填**，string）：刚学完的内容范围

**执行步骤**

1. **学完立刻合上资料**（`immediate`，约 1 分钟）
   - 做什么：在接触资料后不超过 3 分钟内，切断资料，进行第一次提取。不要「先整理完笔记再提取」。
   - 验收线：距离最后一次阅读材料 ≤ 3 分钟
   - 产出：timestamp
2. **写出一页纸**（`extract`，约 3 分钟）
   - 做什么：不看任何资料，写下你能想起的关于本次内容的一切：概念、逻辑、疑问、例子。
   - 验收线：产出 ≥150 字的无参考资料回忆稿
   - 产出：one-pager
3. **标出想不起的**（`mark-gap`，约 2 分钟）
   - 做什么：对照资料，只用红笔在回忆稿上标出漏掉的部分，不改写内容。
   - 验收线：回忆稿上有明确红色标注，且标注处都有「我以为我会但不会」的自评
   - 产出：annotated p

**Agent 契约**

- 输入：session
- 输出：one-pager
- 降级：无需降级，纯文本可执行

**自检问题**

- 这次提取是 3 分钟内做的吗？
- 标红的地方是不是下次真的考？

**达标判据**

- 一周后提取内容命中率 > 70%

### 12. 睡眠巩固（`sleep-consolidation`）

*Sleep Consolidation*

**把难啃的内容安排在睡前学、睡够再复盘，让睡眠帮你把当天的记忆固化下来。**

- **分类**：记忆巩固
- **循证等级**：high —— 有较强实验证据支持（多项对照研究）
- **版本**：0.1.0　**许可**：CC0-1.0

**适用场景**

- ✓ 需要长期记住的硬内容
- ✓ 考前复习安排
- ✓ 背大量材料

**不适用**

- ✗ 需要当堂立刻输出的即时任务

**入参**

- `material`（**必填**，string）：计划睡前学习的材料
- `hours`（可选，number），默认 `7.5`：当晚计划睡眠时长（小时）

**执行步骤**

1. **挑出最该巩固的部分**（`pick`，约 4 分钟）
   - 做什么：从当天学的内容里挑出 3 条最难、最需要长期记住的。不要超过 3 条。
   - 验收线：选定条目数 = 3，且每条都注明了为什么难
   - 产出：重点条目
2. **睡前过一遍**（`evening`，约 10 分钟）
   - 做什么：在入睡前 1 小时内，把这 3 条快速过一遍（朗读或默写均可），不做新内容。
   - 验收线：学习发生在入睡 1 小时内，且未引入新材料
   - 产出：睡前复习记录
3. **保住睡眠时长**（`protect`，约 2 分钟）
   - 做什么：确保当晚睡眠不少于 7.5 小时的计划值。记录实际睡眠时长。
   - 验收线：记录了计划睡眠时长与实际睡眠时长两个数值
   - 产出：睡眠时长记录
4. **醒后立刻检验**（`morning`，约 5 分钟）
   - 做什么：起床后不看书，先写出昨晚那 3 条。统计写出了几条，与睡前正确率对比。
   - 验收线：记录了醒后正确条目数与睡前正确条目数，并给出两者差值
   - 产出：保持率对比
   - 不通过回到：`evening`

**Agent 契约**

- 输入：material, hours
- 输出：重点条目, 睡眠时长记录, 保持率对比
- 副作用：仅写本地文件
- 降级：无工具时：靠自述睡眠时长与晨间默写完成

**自检问题**

- 我昨晚睡够了吗，还是熬了夜？
- 醒后想起来的，是不是睡前最难的那几条？

**达标判据**

- 醒后回忆正确条目数不低于睡前
- 连续 3 天保持率不下降

### 13. 睡前醒后记忆（`sleep-wake-memory`）

*Sleep-Wake Memory*

**把难记的材料安排在睡前过一遍、醒后先测一遍，利用睡眠巩固和前后摄干扰少的窗口提升保持率。**

- **分类**：记忆巩固
- **循证等级**：anecdotal —— 主要来自实践经验与个案，缺少严格实验验证
- **版本**：0.1.0　**许可**：CC0-1.0

**适用场景**

- ✓ 记了就忘
- ✓ 有连夜的记忆任务
- ✓ 想利用睡眠巩固

**不适用**

- ✗ 第二天一早就考的临场内容（直接集中背更即时）

**入参**

- `material`（**必填**，string）：要睡前编码的材料

**执行步骤**

1. **选定材料与时段**（`schedule`，约 4 分钟）
   - 做什么：选定要记的材料，安排在睡前 30 分钟内过一遍，并约定次日醒后先测再干别的事。
   - 验收线：写下了材料与睡前时段；且约定醒后先测
   - 产出：记忆计划
2. **睡前精细编码**（`encode`，约 20 分钟）
   - 做什么：睡前逐条过材料，每条用自己的话复述并想一个例子；不解的标记，不硬背。
   - 验收线：每条都有自述复述；且不解处被标记
   - 产出：睡前编码记录
3. **醒后先测**（`retrieve`，约 10 分钟）
   - 做什么：醒来第一件事，在看手机前合上材料，把能想起的写出或说出，标出想不出的。
   - 验收线：醒后已先于其他活动完成一次回忆；且想不出的条目标出
   - 产出：晨间回忆结果
4. **只补晨间缺口**（`target`，约 12 分钟）
   - 做什么：只对晨间想不出的条目重点巩固，已想起的快速过；连续几天重复此循环。
   - 验收线：仅晨间缺口条目被重点巩固；且循环天数已记录
   - 产出：巩固记录
   - 不通过回到：`encode`

**Agent 契约**

- 输入：material
- 输出：记忆计划, 晨间回忆结果, 巩固记录
- 副作用：仅写本地文件
- 降级：无工具时：睡前列清单、醒后口头自测

**自检问题**

- 我醒后是真的先测，还是先刷了手机？
- 晨间想不出的，是没编码好还是没睡够？

**达标判据**

- 晨间回忆率高于无睡前编码时
- 连续几晚缺口逐晚减少

### 14. 间隔重复调度（`spaced-repetition`）

*Spaced Repetition (SM-2)*

**在「快要忘记」的那一刻复习，用最少的总时长换最长的记忆保持。**

- **分类**：记忆巩固
- **循证等级**：high —— 有较强实验证据支持（多项对照研究）
- **版本**：0.1.0　**许可**：CC0-1.0

**适用场景**

- ✓ 需要长期记住大量事实/术语
- ✓ 需要记住代码 API、命令、外语单词等离散项

**不适用**

- ✗ 只考一次的短期突击（用 active-recall 集中刷）
- ✗ 要学会一项技能而非记住一批事实（用 deliberate-practice 或 project-based-learning）

**入参**

- `items`（**必填**，array）：已有 SRS 条目或待入库材料
- `today`（可选，string）：基准日期，默认今天

**执行步骤**

1. **取出今日到期队列**（`due-query`，约 1 分钟）
   - 做什么：扫描本地 learner-state，列出 next_due ≤ today 的条目，按 due 时间正序排列。若为空，进入步骤 5。
   - 验收线：产出了一份有序队列，或显式声明队列为空
   - 产出：due queue
2. **逐条提取**（`review`，约 15 分钟）
   - 做什么：对每条先做主动回忆（不显示答案），然后才核对。禁止直接给答案。
   - 验收线：每条都产生了先回忆后核对的顺序记录
   - 产出：review log
3. **SM-2 重算间隔**（`reschedule`，约 2 分钟）
   - 做什么：按规范 §5 公式更新 ease_factor / interval_days / repetitions / next_due。q<3 时 interval 重置为 1。
   - 验收线：每条的 next_due > today，且 ease_factor ∈ [1.3, 3.0]
   - 产出：updated state
4. **控制单日时长**（`budget`，约 1 分钟）
   - 做什么：统计今日复习总耗时。若超过 20 分钟，把剩余条目的 next_due 顺延一天，不丢条目。
   - 验收线：单日总时长 ≤ 20 分钟，且条目无丢失（顺延数 = 未复习数）
   - 产出：daily summary

**Agent 契约**

- 输入：items, today
- 输出：review log, updated learner-state.json
- 副作用：写本地 learner-state.json
- 降级：无计算工具时：Agent 直接按规范公式手算，并展示中间值供核对

**自检问题**

- 今天复习的条目里，有多少是我在 1 秒内就答出来的（这些可以降频）？
- 有没有条目连续多天 < 3 分（说明当初就不该入库）？

**达标判据**

- 复习队列长度稳定而非无限增长
- 相同总时长下保持率优于集中复习

### 15. 树状图记忆法（`tree-memory`）

*Tree-Diagram Memory*

**按含义的包含关系把知识组织成一棵层级树，从上位到下位逐层默背，用结构顺序代替零散死记。**

- **分类**：记忆巩固
- **循证等级**：anecdotal —— 主要来自实践经验与个案，缺少严格实验验证
- **版本**：0.1.0　**许可**：CC0-1.0

**适用场景**

- ✓ 知识有清晰层级，如分类体系
- ✓ 一堆并列名词记不住
- ✓ 想把零散点挂到结构上

**不适用**

- ✗ 知识是网络关系而非层级（用概念图更合适）

**入参**

- `scope`（**必填**，string）：要组织成树的知识范围

**执行步骤**

1. **定树根与主干**（`root`，约 6 分钟）
   - 做什么：确定最上位概念作树根，向下分出若干主干，每个主干是该根下的一个大类。
   - 验收线：树根唯一明确；且主干至少 3 个
   - 产出：树根与主干
2. **逐层分到叶**（`branch`，约 15 分钟）
   - 做什么：每个主干继续按包含关系向下分，直到分到最小可记单元；同层按同一标准划分。
   - 验收线：每个主干都分到了叶节点；且同层按同一标准划分
   - 产出：完整层级树
3. **逐层默背**（`climb`，约 10 分钟）
   - 做什么：从树根开始逐层默背，盖住某层复述其下所有子项，卡住的枝标记。
   - 验收线：每层都完成了一次盖层复述；卡住的枝被标记
   - 产出：默背记录
4. **只补断枝**（`repair`，约 8 分钟）
   - 做什么：只重背标记的断枝及其到根的路径，其余不动；隔日重测整棵树。
   - 验收线：仅断枝被重背；且安排了隔日整树重测
   - 产出：补背结果
   - 不通过回到：`climb`

**Agent 契约**

- 输入：scope
- 输出：层级树, 补背结果
- 副作用：仅写本地文件
- 降级：无工具时：纸上画树并逐层默背

**自检问题**

- 我的分层是按包含关系，还是随便归类？
- 盖层后我能从上位推出下位吗？

**达标判据**

- 整棵树可逐层复述
- 断枝经补背后减少
