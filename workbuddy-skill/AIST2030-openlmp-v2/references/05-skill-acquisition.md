# 技能习得 · 执行手册（8 个方法）

> 详细步骤、验收线与 Agent 契约。每个方法的 checkpoint 都是**可判定**的，无法判定就说明这一步没做扎实，不要靠感觉通过。

### 1. 二分定位调试（`bisect-debug`）

*Bisect Debugging*

**出错时别乱猜，用二分法把范围对半砍，几步就把问题锁到具体位置。**

- **分类**：技能习得
- **循证等级**：anecdotal —— 主要来自实践经验与个案，缺少严格实验验证
- **版本**：0.1.0　**许可**：CC0-1.0

**适用场景**

- ✓ 报错但看不出原因
- ✓ 一堆改动后突然坏了
- ✓ 定位复杂问题

**不适用**

- ✗ 错误信息已直接指出位置（直接改即可）

**入参**

- `problem`（**必填**，string）：出问题的系统或流程描述
- `max_steps`（可选，integer），默认 `5`：最多二分几轮

**执行步骤**

1. **先定问题边界**（`bound`，约 6 分钟）
   - 做什么：确认「哪里是好的、哪里是坏的」：找到一个正常工作的输入和一个失败的输入。
   - 验收线：存在一组可对比的正常案例与失败案例，且两者差异被写明
   - 产出：边界案例对
2. **对半砍**（`halve`，约 20 分钟）
   - 做什么：把从正常到失败之间的范围对半切，测中点属于正常还是失败，把范围缩小一半。重复直到范围只剩一处。
   - 验收线：每轮范围减半；且每轮都记录了中点的判定结果
   - 产出：二分过程记录
3. **单点验证**（`confirm`，约 10 分钟）
   - 做什么：对锁定位置单独改动一次，确认问题消失；再改回去确认问题复现。两次都成立才算定位成功。
   - 验收线：完成了「改掉→恢复」与「恢复→复现」两次验证；两者结论一致
   - 产出：验证结论
4. **记入错题本**（`record`，约 5 分钟）
   - 做什么：把「根因 → 判据 → 修法」三行写进错题本，并设定复习时间。
   - 验收线：记录含根因、判据、修法三项；且已设定复习时间
   - 产出：错题记录
   - 不通过回到：`halve`

**Agent 契约**

- 输入：problem, max_steps
- 输出：边界案例, 二分记录, 验证结论
- 副作用：仅写本地文件
- 降级：无工具时：口头引导二分定位，靠提问收窄范围

**自检问题**

- 我是在系统定位，还是在碰运气改？
- 改好之后我验证「改回去会再坏」了吗？

**达标判据**

- 定位过程 ≤ max_steps 轮
- 同类问题下次能直接认出

### 2. 认知学徒（`cognitive-apprenticeship`）

*Cognitive Apprenticeship*

**让高手把原本藏在脑子里的思考过程外放出来：先示范、再带着做、然后放手，最后让你自己讲一遍。**

- **分类**：技能习得
- **循证等级**：medium —— 有一些支持性证据，但结论稳健性中等
- **版本**：0.1.0　**许可**：CC0-1.0

**适用场景**

- ✓ 跟着师傅学手艺
- ✓ 学难以言传的判断力
- ✓ 带新人/带徒弟

**不适用**

- ✗ 有清晰文档和标准流程的任务（直接照文档更快）

**入参**

- `skill`（**必填**，string）：要习得的具体技能
- `expert`（可选，string）：示范者是谁，可留空用 Agent 模拟

**执行步骤**

1. **看高手做一遍**（`model`，约 15 分钟）
   - 做什么：让示范者边做边把判断依据说出来，重点是「为什么这么做」而不是「做了什么」。
   - 验收线：记录中包含 ≥3 处明确的判断依据说明
   - 产出：示范记录
2. **在提示下做一遍**（`coach`，约 25 分钟）
   - 做什么：自己动手做，卡住时示范者只给提示不给答案。记录每处提示。
   - 验收线：完成了一遍尝试；且每处提示都被逐条记录
   - 产出：尝试记录与提示清单
3. **撤掉提示独立做**（`fade`，约 20 分钟）
   - 做什么：不看提示独立完成同一任务。与前一次对比，统计还需要提示的地方。
   - 验收线：独立完成了任务；且给出了与上次相比提示次数的变化
   - 产出：独立完成结果
   - 不通过回到：`coach`
4. **讲一遍自己怎么做的**（`articulate`，约 10 分钟）
   - 做什么：把整个判断过程讲给示范者听，让他指出你漏掉或讲错的环节。
   - 验收线：完成了口头复述；且被指出的遗漏/错误点被记录
   - 产出：讲解记录与反馈

**Agent 契约**

- 输入：skill, expert
- 输出：示范记录, 尝试记录, 讲解反馈
- 副作用：仅写本地文件
- 降级：无工具时：Agent 扮演示范者，用追问代替真人反馈

**自检问题**

- 我能说出高手的判断依据，还是只记住了他的动作？
- 独立做时卡的地方，和上次一样吗？

**达标判据**

- 独立完成时不再需要提示
- 能把判断依据讲给别人听

### 3. 刻意练习（`deliberate-practice`）

*Deliberate Practice*

**把大技能拆成刚好超出当前能力一点点的小任务，重复、即时反馈、逐次纠错。**

- **分类**：技能习得
- **循证等级**：high —— 有较强实验证据支持（多项对照研究）
- **版本**：0.1.0　**许可**：CC0-1.0

**适用场景**

- ✓ 练技能（乐器/编程/运动/写作/演讲）
- ✓ 已经重复很多次但没进步

**不适用**

- ✗ 只是要记住知识（用 active-recall）
- ✗ 刚开始学，还没有基本动作

**入参**

- `skill`（**必填**，string）：要刻意练习的具体子技能，如「写 SQL 的 JOIN」「冷启动开场白」
- `current_level`（**必填**，string）：当前水平描述
- `session_min`（可选，integer），默认 `45`：单次练习时长，超时即停（刻意练习要求全程专注不疲劳）

**执行步骤**

1. **找准当前瓶颈**（`diagnose`，约 10 分钟）
   - 做什么：让用户做一次目标技能的完整尝试，Agent 记录：哪一环出错最多。只挑出错最多的那一环，不列清单。
   - 验收线：产出一个明确的最弱环节描述，不是「整体都不行」
   - 产出：bottleneck
2. **设计针对性小练习**（`design-drill`，约 5 分钟）
   - 做什么：针对该瓶颈设计 3–5 个难度递增的小练习，每个练习 2–5 分钟。难度上限：比当前水平难一档。
   - 验收线：练习数 ≥3，且每个都有明确的一句话通过标准
   - 产出：drill list
3. **重复—反馈—归因循环**（`loop`，约 25 分钟）
   - 做什么：每做一个练习：立即给具体反馈（哪里好、哪个动作错了）→ 让用户重做一次 → 记录归因（是知识不足/动作不熟/注意力散）。同一练习最多重做 3 次，超过则说明难度设计有问题，必须降档。
   - 验收线：每个练习至少完成 2 次重做，且 3 次未过的一定被记录为「难度过高」
   - 产出：loop log
4. **提炼可复用规则**（`consolidate`，约 5 分钟）
   - 做什么：把本轮归因中反复出现的那一条，写成一句下次直接可执行的规则（如「换手时先稳肩再转腕」）。
   - 验收线：产出一条动词开头的具体规则，且能对照本次录像验证
   - 产出：one rule

**Agent 契约**

- 输入：skill, current_level, session_min
- 输出：bottleneck, drill list, loop log, one rule
- 副作用：仅写本地文件
- 降级：无法获取真实操作反馈时（无视频/无传感数据）：明确告知用户「缺反馈源」，改为纯自评 + 录像复盘，不假装给了客观反馈

**自检问题**

- 这一小时里，我是在重复已经会的东西，还是在攻最不会的那一点？
- 我拿到的反馈是「再练练」这种废话吗？

**达标判据**

- 同一练习的成功率逐次上升
- 能说出一条以前不知道的规则

### 4. 心理演练（`mental-rehearsal`）

*Mental Rehearsal*

**不动手，只在脑中把整个操作流程完整过一遍，包括每个分支和出错时的应对。**

- **分类**：技能习得
- **循证等级**：medium —— 有一些支持性证据，但结论稳健性中等
- **版本**：0.1.0　**许可**：CC0-1.0

**适用场景**

- ✓ 动手机会少或成本高
- ✓ 上台/比赛/演示前
- ✓ 巩固已学流程

**不适用**

- ✗ 从没实际做过的全新流程（脑中演练会建立错误模式）

**入参**

- `procedure`（**必填**，string）：要在脑中演练的具体流程

**执行步骤**

1. **写出完整流程**（`script`，约 10 分钟）
   - 做什么：把流程按顺序写成步骤，含判断分支（如果出现 X 就走 Y）。
   - 验收线：步骤数 ≥ 4，且至少含 1 个判断分支
   - 产出：流程脚本
2. **闭眼过一遍**（`visualize`，约 12 分钟）
   - 做什么：闭眼按脚本在脑中走完全程，想象每个动作和反馈。卡住就记下卡在哪一步。
   - 验收线：完成了一次全程演练；卡壳步骤被记录
   - 产出：演练记录
3. **演练出错分支**（`branch`，约 10 分钟）
   - 做什么：针对每个判断分支，在脑中走一遍「出错时怎么办」的路径。
   - 验收线：每个分支的异常处理路径都被演练过；分支数与演练记录条数一致
   - 产出：分支演练记录
4. **实操对照**（`compare`，约 15 分钟）
   - 做什么：找机会真正做一次，记录与演练不一致的地方，回头修订流程脚本。
   - 验收线：完成了一次实操；且列出了与演练不一致之处并给出修订
   - 产出：对照结果与修订
   - 不通过回到：`script`

**Agent 契约**

- 输入：procedure
- 输出：流程脚本, 演练记录, 对照结果
- 副作用：仅写本地文件
- 降级：无工具时：文字化演练，靠自述记录卡点

**自检问题**

- 我演练的是完整流程，还是只演了顺利的那条路？
- 真正做的时候，哪里跟我脑中不一样？

**达标判据**

- 实操时无计划外中断
- 流程脚本经实操修订后无遗漏分支

### 5. 721 行动学习（`project-based-learning`）

*70-20-10 Action Learning*

**10% 学理论 / 70% 做真实任务 / 20% 复盘，把学习时间强制分配到动手比例上，避免「只学不用」。**

- **分类**：技能习得
- **循证等级**：anecdotal —— 主要来自实践经验与个案，缺少严格实验验证
- **版本**：0.1.0　**许可**：CC0-1.0

**适用场景**

- ✓ 要学职业技能（写作/编程/设计/数据）
- ✓ 读了三个月书没产出
- ✓ 公司内训

**不适用**

- ✗ 纯理论学科（数学定理、法条）
- ✗ 还不会用就想上手（先补最小基础）

**入参**

- `skill`（**必填**，string）：要通过项目练的能力，须有真实可交付的产出物
- `real_task`（**必填**，string）：一个真实存在的、有人要的产出
- `weeks`（可选，integer），默认 `6`：项目周期（周）。周期太短形不成反馈闭环，太长会烂尾

**执行步骤**

1. **先定真实任务**（`task-first`，约 20 分钟）
   - 做什么：先定一个**真实存在、有人要、能在数周内交付**的任务（给朋友做一次 PPT / 上线一个小功能 / 写一篇能发表的文章）。没有真任务的，先找一个人问「你最近需要什么帮助」。
   - 验收线：任务有明确接收方、明确交付物、明确截止日
   - 产出：real task brief
2. **只学任务卡住的部分（10%）**（`plan-10`，约 30 分钟）
   - 做什么：针对任务倒推：现在卡在哪？只学**当前这一步需要的**那部分知识，不要系统学整门课。记录这次学了什么、用了哪一条。
   - 验收线：列出了本次要学的 3–5 个具体问题，且每个都直接对应任务中的某个卡点
   - 产出：targeted syllabus
3. **动手做（70%）**（`do-70`，约 120 分钟）
   - 做什么：直接做，遇到不会就查，查完继续做。**记录每一次「我以为我会但不会」的时刻**——这比做出来的成品更值钱。
   - 验收线：产出了可交付的中间成果；卡点时刻记录 ≥5 条
   - 产出：交付物 + 卡点记录
4. **复盘（20%）**（`review-20`，约 30 分钟）
   - 做什么：回答三问：这次做成的关键动作是什么？卡住的地方暴露了我缺什么？下次遇到同类任务，第一步该做什么？写下一条可执行规则。
   - 验收线：产出一条动词开头的具体规则，且能对照本次产出验证
   - 产出：复盘 + one rule
5. **接下一个更难的任务**（`iterate`，约 10 分钟）
   - 做什么：如果交付被接受，找一个难度高一级、交付物相似但要求更高的任务。重复本流程。难度必须上升，否则是在原地重复。
   - 验收线：新任务的难度确实高于上一轮，且差距不是靠加班补的
   - 产出：next task

**Agent 契约**

- 输入：skill, real_task, weeks
- 输出：real task brief, 复盘
- 副作用：写本地文件
- 降级：用户没有真实任务需求时：Agent 必须提示「先去找一个真实需求」，**禁止**用虚拟练习项目替代——这是本方法的核心机制，替代即失效

**自检问题**

- 这次学的东西，真的被用在交付物上了吗？
- 我记录卡点的时刻，是不是都记得当时在想什么？

**达标判据**

- 每轮都有真实交付物
- 卡点记录逐轮变少

### 6. 脚手架渐隐（`scaffold-fading`）

*Scaffold Fading*

**先给足提示和模板把事情做成，然后一轮轮抽掉辅助，最后不留痕迹也能独立做。**

- **分类**：技能习得
- **循证等级**：medium —— 有一些支持性证据，但结论稳健性中等
- **版本**：0.1.0　**许可**：CC0-1.0

**适用场景**

- ✓ 学新东西总做不出来
- ✓ 带教/培训场景
- ✓ 想摆脱对模板的依赖

**不适用**

- ✗ 已经能独立完成、只是想提速

**入参**

- `task`（**必填**，string）：要掌握的具体任务
- `rounds`（可选，integer），默认 `3`：渐隐轮数

**执行步骤**

1. **第一轮：全模板**（`full`，约 20 分钟）
   - 做什么：提供完整模板、步骤与示例，让学习者照着做一遍做出成品。
   - 验收线：学习者在全模板辅助下产出了 1 件成品
   - 产出：首轮成品
2. **第二轮：抽掉细节**（`partial`，约 20 分钟）
   - 做什么：保留步骤框架，隐去具体写法与提示，让学习者补齐空缺部分。
   - 验收线：学习者在仅保留框架的情况下补齐了空缺并产出成品
   - 产出：二轮成品
3. **第三轮：只给目标**（`bare`，约 20 分钟）
   - 做什么：只说明要做什么和验收标准，不给任何模板。让学习者独立完成。
   - 验收线：学习者无任何模板辅助下独立完成并通过验收标准
   - 产出：三轮成品
   - 不通过回到：`partial`

**Agent 契约**

- 输入：task, rounds
- 输出：各轮成品
- 副作用：仅写本地文件
- 降级：无工具时：对话式逐步撤除提示

**自检问题**

- 我去掉的是「辅助」，还是把「要求」也一起去掉了？
- 不给模板时卡住的地方，是记忆问题还是判断问题？

**达标判据**

- 无模板独立产出且达标
- 每轮辅助递减且成品质量不下降

### 7. 影子跟读法（`shadowing`）

*Shadowing*

**放着母语音频慢半拍同步复述，强迫耳朵、嘴巴、节奏对齐，专治看得懂但说不出、听得清却反应慢。**

- **分类**：技能习得
- **循证等级**：medium —— 有一些支持性证据，但结论稳健性中等
- **版本**：0.1.0　**许可**：CC0-1.0

**适用场景**

- ✓ 练口语语感和发音节奏
- ✓ 听力反应慢
- ✓ 学到会读不会说的阶段

**不适用**

- ✗ 完全零基础的语音（先学音标再跟读）

**入参**

- `audio`（**必填**，string）：带文稿的母语音频
- `lag_ms`（可选，integer），默认 `500`：落后原声的毫秒数
- `rounds`（可选，integer），默认 `3`：跟读轮数

**执行步骤**

1. **选材并通听**（`prep`，约 8 分钟）
   - 做什么：选一段 30-60 秒、带文稿的母语音频，先不看文稿完整听一遍，标出听不懂的位置。
   - 验收线：音频时长在 30-60 秒；且标出了听不懂的位置
   - 产出：标疑点的音频
2. **慢半拍跟读**（`shadow`，约 15 分钟）
   - 做什么：播放音频，比原声晚约 lag_ms 毫秒复述，尽量模仿语调重音；跟不上就暂停重来，不跳过。
   - 验收线：完成 rounds 轮跟读；且每轮均晚于原声开口，未与原声同时
   - 产出：跟读记录
3. **对照文稿找差距**（`diff`，约 8 分钟）
   - 做什么：现在看文稿，标出跟读中漏词、错音、语调跑偏的位置，逐条记下。
   - 验收线：列出了漏词、错音、语调三类差距；且每类定位到具体词句
   - 产出：差距清单
4. **收窄差距重跟**（`loop`，约 12 分钟）
   - 做什么：针对差距清单重跟，每轮统计仍出错的条目数，直到该轮新增出错为 0 或达到 rounds 上限。
   - 验收线：给出了每轮出错条目数；且末轮出错数不高于首轮
   - 产出：收窄结果
   - 不通过回到：`shadow`

**Agent 契约**

- 输入：audio, lag_ms, rounds
- 输出：差距清单, 收窄结果
- 副作用：仅写本地文件
- 降级：无音频时：由 Agent 朗读，用户慢半拍复述

**自检问题**

- 我是真的在跟，还是等原声念完才开口？
- 差距清单里的问题，下一轮真的少了吗？

**达标判据**

- 末轮漏词与错音数不超过首轮一半
- 不看文稿也能跟上语速

### 8. 西蒙学习法（`simon-learning`）

*Simon Learning Method*

**一次只锁定一个目标，连续数月每天投入整块时间深耕，用单点饱和攻击代替四处浅尝。**

- **分类**：技能习得
- **循证等级**：anecdotal —— 主要来自实践经验与个案，缺少严格实验验证
- **版本**：0.1.0　**许可**：CC0-1.0

**适用场景**

- ✓ 想在一个领域达到可用水平
- ✓ 总是同时开好几个坑都半途而废
- ✓ 有整块时间能长期投入

**不适用**

- ✗ 只有几天零碎时间
- ✗ 目标本身还没选对

**入参**

- `goal`（**必填**，string）：唯一要攻下的目标，写成「能做到X」
- `daily_min`（可选，integer），默认 `240`：每天深耕的分钟数
- `months`（可选，integer），默认 `6`：持续月数

**执行步骤**

1. **锁定唯一目标**（`pick`，约 6 分钟）
   - 做什么：写下这一个要攻下的目标，写成「能做到X」而非「学完X」，并把同期其他学习计划显式列出后删除，只保留这一个。
   - 验收线：写下 1 个以「能做到X」表述的目标；且同期其他学习计划被列出并删除
   - 产出：唯一目标陈述
2. **切成可验收的子能力**（`slice`，约 10 分钟）
   - 做什么：把目标拆成 4-6 项按顺序习得的子能力，每项写一条「做到什么算会」的可核对描述。
   - 验收线：子能力 4-6 项；且每项都有一条可核对的达标描述
   - 产出：子能力清单
3. **每天整块投入**（`daily`，约 240 分钟）
   - 做什么：每天在固定时段投入 daily_min 分钟，只练当前子能力；做完在日志记一行日期、内容、卡点。
   - 验收线：连续记录天数 = 计划天数；且每天日志含日期、内容、卡点三要素
   - 产出：每日深耕日志
4. **逐项过关**（`gate`，约 20 分钟）
   - 做什么：每项子能力用一条实作或真题验收，达标才进下一项；未达标就地重练，不跳过。
   - 验收线：每项子能力都有一次验收结果记录；未达标项被重练而非跳过
   - 产出：过关记录
   - 不通过回到：`daily`

**Agent 契约**

- 输入：goal, daily_min, months
- 输出：唯一目标, 子能力清单, 深耕日志, 过关记录
- 副作用：仅写本地文件
- 降级：无工具时：用纸质日志记录每日投入与验收

**自检问题**

- 这一小时我真的只砸在这一个目标上吗？
- 过关是凭感觉，还是凭那条可核对的达标描述？

**达标判据**

- 按计划天数完成深耕，无连续 2 天中断
- 全部子能力通过验收
