# OpenLMP 落地路线图（务实版）

> 这份文档故意写得比《完整设计方案》保守得多。
> 理由：宏大愿景负责吸引人，务实路线负责让项目活下来。

---

## 一、先说结论：三个必须砍掉的东西

原始设计里有三处**在工程上不成立**，如果照做，项目会在第 3 个月死掉。

| 原始设计 | 问题 | 务实做法 |
|---|---|---|
| 「收益分成」写进公共协议 | 分成需要结算主体 → 有结算主体就有中心 → **与去中心化目标逻辑死锁** | 分成属于「可选商业层」，协议层不碰。公共协议永不涉及钱 |
| 「2/3 治理节点投票」 | 没有 10 个高质量 Skill，投票系统是空转的精密机器 | 治理推迟到 v1.0 之后，且形式应为「联盟 + 基金会」而非 P2P 链上 |
| 「IPFS + uAgents + 区块链存证」 | 全球教育工作者不会为了写一个 JSON 先装 Python 环境 | v0.1 **零依赖单文件**。IPFS/git 双锚定放 v0.3，且是「可选同步方式」而非前置条件 |

**最核心的一条判断：**

> 这套设计里真正稀缺、真正不可被中心化复制的，只有 **Skill 契约 + Skill 库**。
> 路由、节点、治理都是后续，而且都可能以「有中心但不垄断」的联盟形式存在，不必强行 P2P。

理由很简单：**Skill 库是内容，治理是形式。内容会自己活下去，形式会死。**

## 二、当前已交付（v0.1，可运行，不是 PPT）

```
OpenLMP/
├── SPEC.md                       协议规范 v0.1（含「不做什么」章节）
├── schema/
│   ├── skill-0.1.json            Skill JSON Schema
│   └── learner-state-0.1.json    本地状态 Schema
├── skills/                       10 个核心方法（全部 CC0）
│   ├── _template.json            贡献者样板
│   ├── feynman.json              费曼学习法
│   ├── active-recall.json        主动回忆练习
│   ├── spaced-repetition.json    间隔重复调度（SM-2）
│   ├── deliberate-practice.json  刻意练习
│   ├── elaborative-interrogation.json  精细追问法
│   ├── retrieval-spread.json     高频短时提取
│   ├── dual-coding.json          双重编码
│   ├── concept-map.json          概念图构建
│   ├── learning-journal.json     学习日志与错因归因
│   └── transfer-question.json    迁移提问训练
├── runtime/lmp.py                参考执行器（零依赖，~600 行）
└── registry/registry.json        内容寻址清单（CID）
```

**质量保证不是口号，是可执行的代码：**

```bash
python runtime/lmp.py selftest
```

包含 7 类测试，其中 3 类是**反向测试**（故意注入违规，必须被拒绝）：

| 测试 | 注入的违规 | 期望结果 |
|---|---|---|
| 纯度测试 | 「请先注册账号并输入 API Key」 | 拦截 ✓ |
| checkpoint 测试 | 「深刻理解这个概念」 | 判为不可判定 ✓ |
| 循证测试 | `evidence: high` 但无引用 | 拒绝（防虚标）✓ |

外加 SM-2 四项边界（q=0 归 1 天 / 首答 1 天 / 二答 6 天 / 三答 ×ease）+ ease 下界锁定 + CID 稳定性。

**当前状态：全部通过 ✅**

## 三、三条命令就能用（零门槛）

```bash
python runtime/lmp.py list                              # 看有哪些方法
python runtime/lmp.py recommend "我记住了但过两天就忘"   # 本地检索，不联网
python runtime/lmp.py run feynman --topic "间隔重复"     # 打印执行剧本
```

关键：**接入成本是「把 JSON 贴给 AI」。** 不装东西、不注册、不填 Key。
这是全项目最重要的产品决策，比任何架构设计都重要。

## 四、分期路线（每期只有一个成功标准）

### v0.1 → v0.2（1–3 月）：把库做厚 + 找到真实用户

| 项 | 内容 |
|---|---|
| 交付 | 40 个 Skill；路由规则格式（`knowledge-route-0.1.json`）；终端/桌面 SRS UI |
| **成功标准** | **有 10 个陌生人在没有任何指导的情况下，用它学完了一门课** |
| 失败信号 | 只有我们自己和身边人在用 |

具体动作：
1. 补 30 个方法（拆解/批判性阅读/SQ4R/番茄/错题本/主题精读/卡片盒笔记/费曼+间隔组合…）
2. 把 OpenLMP 打包成 WorkBuddy skill（现有 40+ skill 体系已有分发能力，直接复用）
3. 在官网 AI 导航页加一个入口（已有 GEO 策略，新内容天然吃收录）
4. 找 10 个真实学习者做 7 天陪跑，逐条记录他们卡在哪

### v0.2 → v0.3（3–12 月）：验证「不可垄断」是真的

| 项 | 内容 |
|---|---|
| 交付 | IPFS + git 双锚定；跨设备本地同步（用户自选端点）；至少 3 个独立第三方实现协议 |
| **成功标准** | **有人在我们不参与的情况下，独立提交了一个我们认可的 Skill** |
| 失败信号 | 所有提交都只能走我们这唯一的 PR 通道 |

关键：这一步的产出不是技术，是**「我们不在场也能运转」的证据**。

### v0.3 → v1.0（12 月后）：治理形式由社区决定

到那时才谈：
- 联盟 / 基金会（大概率是这个，而不是纯 P2P）
- 资金池（必须多签 + 公开，但**不能进协议层**）
- 争议裁决（那时已有真实争议可裁，现在没有）

## 五、第一批贡献者从哪来（这个比技术难）

不要指望「投个 GitHub 就有人来」。现实路径：

| 来源 | 打法 | 为什么有效 |
|---|---|---|
| **现有 skill 生态** | 打包成 WorkBuddy skill，我们已有 40+ skill 的分发通道 | 分发成本≈0 |
| **高校教育技术老师** | 直接邮件邀请，附「一条命令可跑」的 demo | 老师最缺「不用折腾就能用」的东西 |
| **考研/考公社群** | 发布「用这 10 个方法复习」的免费工具 | 有即时个人收益才会用 |
| **GEO 内容** | 把每个 Skill 写成独立可索引网页 | AI 引擎会替我们带流量 |
| **不靠谱的路径** | 空投 uAgents / 链上激励 / 基金会招募 | 劝退 99% 的人 |

## 六、关于「消除贫困 / 治理环境」的终局（诚实评估）

原始设计最后一段提到用智能体协作攻克重大难题。方向我认同，但要把话说清楚：

**OpenLMP 目前只是「学习方法公共化」。它与消除贫困之间隔着三层：**

1. **方法平权 ≠ 机会平权**。知道费曼学习法，解决不了没有教材、没有网络、没有时间的问题
2. **方法平权 ≠ 能力平权**。方法需要认知负荷才能用，教不会底层能力的人用不好高级方法
3. **不违反各国法律** —— 这是硬约束，不是加分项。具体到：
   - 跨境数据流动（GDPR / 中国个保法 / 各法域）
   - 未成年人数据（COPPA / GDPR-K / 中国未成年人保护法）
   - 「不替代正规教育」的定位边界（学历/认证属国家管理范畴）
   - 「免费」表述在部分语境下的合规边界（用户自己就明令官网禁「免费」二字）

**更现实的路径**：把方法平权做到极致 → 降低「学会任何东西」的门槛 → 让更多人具备提出问题和解决本地问题的能力。宏大目标只能由一代人自己走完，任何项目都无法跳过中间步骤。

我不认为一个协议能直接消除贫困。但它能让「自学」这件事的成本低一个量级——**这已经是能用代码做到的极限了。**

## 七、本周可执行清单

```
□ 1. 找 3 个真实学习者，各自跑通一条 run 命令，记录他们的问题
□ 2. 补 5 个 Skill（SQ4R / 批判性思维 / 卡片盒 / 错题本 / 间隔+费曼组合）
□ 3. 打包成 WorkBuddy skill，接入现有分发
□ 4. 在官网 AI 导航页挂入口（SEO/GEO 双收益）
□ 5. 写一篇「为什么我砍掉了链上治理」的公开说明 —— 立场比技术更难被抄
```

第 5 条值得单独说：**公开说明「为什么不做什么」，本身就是最难被中心化平台复制的资产。** 因为大公司不会发这种声明。
