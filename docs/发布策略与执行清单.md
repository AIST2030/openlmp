# 发布策略与执行清单

> 问题：OpenLMP 是我发起的，**发布到哪里？**
> 答案先给：**发布到「开源代码托管平台」，而不是「网站」或「应用商店」。**
> 理由不是流量，是合规 —— 见 §1。

---

## 1. 关键判断：发布行为本身决定你在不在监管射程内

《生成式人工智能服务管理暂行办法》第二条：

> 「利用生成式人工智能技术**向中华人民共和国境内公众提供**生成文本……服务，适用本办法。
> **行业组织、企业、教育和科研机构、公共文化机构、有关专业机构等研发、应用生成式人工智能技术，未向境内公众提供生成式人工智能服务的，不适用本办法。**」

第七条：
> 「行业组织、企业、教育和科研机构……**未向境内公众提供服务**的，不适用本办法」

**这是整个 OpenLMP 唯一的合规命根子。**

| 你做什么 | 是否「向公众提供服务」 | 是否触发办法 |
|---|---|---|
| 发布 Markdown 规范 + JSON 文件 | ❌ 不是服务，是文档 | ✅ 不适用 |
| 任何人自行下载后跑本地脚本 | ❌ 服务提供者是「他自己」 | ✅ 不适用 |
| 做一个网站，用户输入问题、服务器调 LLM 返回结果 | ✅ **是服务** | ❌ **需备案 + 安全评估** |
| 在公众号发介绍文章 | ❌ 不是服务 | ✅ 不适用 |
| 收集用户学习数据 | ❌ 但触及个保法 | ⚠️ 单独风险 |

**结论：发布到 Git 类代码托管平台 = 安全区。做成在线 Web 服务 = 进监管区。**

> 这不是钻空子，而是「方法公共化」这件事**天然就该是文件形态**。
> 一旦它变成需要服务器的服务，它就必须变成一个可以被关停的东西 —— 那就背叛了整个设计目标。

## 2. 发布到哪里：四层，都有明确分工

### 第一优先：GitHub（国际主阵地）

| 项 | 值 |
|---|---|
| 地址 | `github.com/<你的ID>/openlmp` |
| 许可 | 已有 `LICENSE`（CC0-1.0 官方全文，7KB） |
| 可见性 | **Public** |
| 为什么要 | 唯一真正的全球公共基础设施平台。协议要全球流通，就必须先住在这里 |

⚠️ **GitHub 的现实问题**：中国大陆访问不稳定。所以它不能是唯一阵地。

### 第二优先：AtomGit（国内主阵地，开放原子基金会）

这是你文心方案里唯一**真正选对了**的一项。我核实过：

| 项 | 值 |
|---|---|
| 平台 | AtomGit（开放原子开源基金会旗下），`atomgit.com` |
| 性质 | 中立官方开源基础设施，非商业公司 |
| 注册 | 邮箱/手机号，可直接用 GitHub 账号登录 |
| 实名 | 需邮箱验证；建公开仓库需完善昵称头像 |
| 优势 | 无墙、国产、稳定、一套账号打通代码/模型/数据集/算力 |

**战略价值 > 流量价值**：
项目挂在一个「中立官方开源基金会」名下，比挂在任何商业公司名下都更难被私有化。
这本身就是防垄断的一部分。

### 第三优先：Codeberg / Gitee（可选镜像）

| 平台 | 适合场景 | 注意 |
|---|---|---|
| **Codeberg** | 欧洲非营利、GDPR、开源纯度最高 | 需代理，国内访问一般 |
| **Gitee** | 国内老牌，中文生态好 | ⚠️ 强制实名；敏感内容可能被要求整改；Pages 需实名后才开 |
| **GitCode** | GitLab 底子，企业级 | 个人用偏重 |

**建议**：Codeberg 可挂（保欧洲生态）；**Gitee 谨慎**，实名 + 内容审查对「去中心化教育」这种题材有额外风险。

### ❌ 明确不发布到

| 平台 | 为什么不 |
|---|---|
| 微信公众平台 / 小商店 | 生态封闭，无法 fork，只能阅读 —— 协议流通性归零 |
| 知乎/小红书 | 内容平台不是代码托管，会把协议「文章化」，且无法版本化 |
| 应用商店 | **一旦上架成为「应用」，就必须备案 + 主体 + 隐私政策**，打破 §1 的合规豁免 |
| 自己的服务器 | **同样会变成「向公众提供服务」**（哪怕静态站，只要挂 API 调用） |

## 3. 一份可执行的发布清单（照做即可）

### 第 0 步：本地准备（已完成）

```bash
cd E:/视频创作/AIST2030/OpenLMP
python runtime/lmp.py selftest     # 必须全绿
```

当前状态：✅ 10 个 Skill 全部校验通过，7 类自检全绿，零第三方依赖。

### 第 1 步：建 Git 仓库并首次提交

```bash
cd E:/视频创作/AIST2030/OpenLMP
git init
git add .
git commit -m "feat: OpenLMP v0.1 — 学习方法协议规范 + 10 个 CC0 Skill + 零依赖执行器"
```

建议提交前先补 `.gitignore`（排除 `learner-state.json`，那是你个人数据，**绝不能提交**）：

```
learner-state.json
__pycache__/
*.pyc
.idea/
.vscode/
```

### 第 2 步：推到 GitHub

在 https://github.com/new 建仓，命名为 `openlmp`，**不要**勾选添加 README/LICENSE（本地已有），然后：

```bash
git remote add origin https://github.com/<你的ID>/openlmp.git
git branch -M main
git push -u origin main
```

### 第 3 步：推到 AtomGit（镜像）

在 atomgit.com 建同名公开仓，然后：

```bash
git remote add atomgit https://gitcode.com/<你的ID>/openlmp.git   # AtomGit 的 git 地址
git push -u atomgit main
```

### 第 4 步：给两个仓库都打 tag

```bash
git tag -a v0.1.0 -m "OpenLMP v0.1：协议规范 + 10 个 Skill，零依赖可运行"
git push origin v0.1.0
git push atomgit v0.1.0
```

> **tag 很重要**。因为 Skill 用 CID 内容寻址，git tag 给的是「这一版规范整体不可变」。
> 两者叠加 = 「协议不可被悄悄改掉」这个承诺有了技术证据。

### 第 5 步：域名解析（可选，但建议）

如果要给自己的官网挂一个入口，**只在官网挂静态说明页，不挂任何调用 AI 的功能**：

```
https://你的域名/openlmp/     → 纯静态介绍 + 指向 GitHub/AtomGit 仓库
```

⚠️ **绝不能在站内做「输入需求 → 调 LLM 返回学习计划」**。一旦做了，官网就从「信息展示」变成「向公众提供生成式 AI 服务」，触发备案义务，且与你现有主体资质产生新的合规责任。

## 4. 内容分发：README 是主战场，不是你的朋友圈

真正会被人看到的不是仓库，是 **README 和方法页**。所以：

| 载体 | 内容 | 状态 |
|---|---|---|
| **GitHub README** | 项目门面。已写好，含 30 秒上手 | ✅ 已完成 |
| **每个 Skill 一个可索引页面** | 方法解释 + 适用场景 + CID | 🔵 建议后续做（GEO 红利） |
| **官网 AI 导航页挂入口** | 指向仓库，不是复制内容 | 🔵 建议做 |
| **公众号长文** | 讲理念，不讲功能 | ⚠️ 注意：一旦写「帮你生成学习计划」并引流到可用工具，需谨慎 |

**为什么强调「指向仓库」而不是「复制内容」**：
复制内容 = 你成为唯一源，会腐烂、被抄、无法版本化。
指向仓库 = 永远是最新版，且别人 fork 你也无所谓（这正是目标）。

## 5. 三个必须坚持的发布纪律

### 纪律一：仓库里永远不出现你的个人信息

- ❌ 不放 contact info（你的电话/邮箱不进代码仓）
- ❌ 不放个人身份证明类信息
- ✅ 想留联系方式，只在你自己的官网页面，且**与代码仓物理分离**

理由：协议仓一旦有个人信息 = 你个人成了项目的单点故障。去掉 = 你和项目解绑。

### 纪律二：永远先发 CC0，再发任何商业版

如果你将来真要做商业层（我认为可以，但要走 §6 条件），
**CC0 版本必须已经在公开仓库存在至少 6 个月**。

这不是道德要求，是商业护城河：那时你已经证明了「我真的一分钱没收过」。

### 纪律三：不接受任何形式的独家授权

一旦签了独家，整个「无法被垄断」的承诺当场作废 —— 而且是**协议层面的作废**，比公司层面更严重。

## 6. 如果将来一定要商业化（唯一合法路径）

前提：**公开协议版本已独立运行 6 个月以上，且你是唯一作者。**

| 允许 | 禁止 |
|---|---|
| 为特定场景做「本地私有部署版」（用户自己跑，数据不出机器） | 把 CC0 Skill 闭源私有化 |
| 做企业内训时的部署 + 培训服务 | 把协议字段改名后申请「原创」 |
| 做基于协议的付费咨询/定制 Skill（原创部分可收费） | 「官方认证」标签收费 |

**一句话：卖服务可以，卖「垄断协议」不行。**
